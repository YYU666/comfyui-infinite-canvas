# 原始高模 AO 与 PartField 分区对照

日期：2026-11-04。计划文档 1.1.15；本地开发，未发布。软件版本未递增。

## 结论与纠正

用户指出1772面LOD0过低，不能作为岩壁凹槽和大块面识别的充分依据。本轮直接读取1,998,143面的原始OBJ，未减面、重建或修改源几何。以同机位、相同采样预算对照低模。

原先AO从低模面心取样，即使遮挡射线命中高模，采样布局和分区仍丢失大量高模结构。本轮的高模AO细节明显恢复。PartField高模区域在当前正面视图更连贯，但仍有噪点；没有真值，不宣称识别准确率提升或已经得到合格UV切缝。

原始高模SHA256：`8ad2a900b9387cc13b144f0bc335b65895cbd4458725f62cba94505d78b0bc99`。
低模SHA256：`4290c4532a511813254b1cae0634ce2d284fe6beb64698ee2cfcdb01c622478d`。

## CPU AO

完整几何构建Open3D BVH，固定正面480×360主射线找到真实表面；每命中点32条余弦半球AO射线，距离为高模包围盒对角线的8%。高模约4.05万个命中点、129.6万条AO射线；低模预算接近。背面几何参与遮挡，但本轮只对正面可见表面取样，不是全表面AO烘焙。

| 指标 | 原始高模 | 1772面低模 |
|---|---:|---:|
| 两次独立进程端到端时间 | 17.17 / 17.51秒 | 3.90 / 4.02秒 |
| 读取及哈希 | 12.14 / 12.34秒 | 约0.005秒 |
| BVH构建 | 约1.1秒 | 不足0.001秒 |
| AO射线阶段 | 约0.16秒 | 约0.14秒 |
| 进程树轮询峰RSS | 610 / 651 MiB | 192 / 190 MiB |
| 子进程OS高水位RSS | 约667 MiB | 约179 MiB |
| CUDA占用 | 无 | 无 |

两种内存测量边界不同：轮询包含进程树但会漏掉瞬时峰值，OS高水位来自实际计算进程。高模报告约0.65GiB，不以整卡后台显存冒充本算法消耗。两次AO结果各自完全一致。共同可见像素AO平均绝对差0.165仅表示结果不同，不是准确率。

另试了平滑法线+深度的屏幕空间连通块：80°种子角规则几乎把正面合成整块，高模仅2个不少于16像素的区域。这是负结果，不能用于声称完成大块面语义识别。

1200×900展示图由480×360采样放大，未增加测量精度。证据：`.cache/native3d/high-analysis/comparison.json`、`resource-summary.json`、`high-1/`、`high-2/`、`low-1/`、`low-2/`。

## GPU PartField

使用已下载的官方模型，两种几何均从真实表面取100000个编码点、32768个神经查询点，FP16、10000点分块，同归一化和随机种子。8区为主对照，12区复用同一组特征聚类，没有再次神经推理。单面查询上限64使低模发生重新分配，这一点与不限制上限的纯面积采样有差别。

| 指标 | 原始高模 | 1772面低模 |
|---|---:|---:|
| 神经前向 | 1.439秒 | 1.910秒 |
| 模型载入+前向+8/12区聚类 | 7.208秒 | 8.004秒 |
| 上述进程峰RSS | 3.096 GiB | 3.039 GiB |
| Torch峰分配/峰保留 | 1.0005 / 1.082 GiB | 相同 |
| 原面投射阶段（含再次读源及保存） | 16.389秒 | 0.022秒 |
| 查询点实际覆盖原面 | 32386面，1.62% | 1771面，99.94% |

高低共同准备阶段13.232秒，其中高模采样0.994秒、低模采样0.115秒，主要额外成本来自OBJ读取。准备和投射未与推理进程合并监测，因此这里没有全流程峰内存或单模型端到端AI计时；不能把7–8秒写成全部处理耗时。每种仅一次串行实测，不能推断高模更快。这次在3090Ti上测量，显存预算低不等于8GB显卡已实机验收。

多数高模面没有独立神经查询：查询特征经MiniBatchKMeans聚类，再按16个空间近邻、法线夹角≤60°、归一化距离≤0.03投射回原面。无支持的10024面、0.3388%表面积保留为-1/灰色，不强填。没有做区域拓扑连通性或小碎片清理，这些标签只能作为分区建议，不能直接当最终切缝。

图上高低颜色按当前视图最大重合匹配，不保证语义一致。正面同机位图不代替背面检查。

原始证据在本机外置模型目录下 `uv-segmentation/tests/high-segmentation-20261104/`：`comparison-receipt.json`、8/12区对照图、查询特征、原面标签和映射。实验脚本在 `.cache/native3d/high-segmentation/`，模型权重未改。

## 画布与交互

- 高模AO、低模AO、PartField对照作为静态诊断图片，通过当前页上传和保存；虚线明确标记“诊断参考”，记录源模型及图片资产路径。
- 不覆盖原始模型、现有UV和LOD链；本轮不自动开展新的UV展开。
- 模型静态图片双击大图支持指针中心滚轮25%–800%缩放、拖动、100%、适应窗口。滚轮不穿透到底层画布，Esc/关闭清理监听。
- 捕获阶段排除3D弹层的双击和右键，避免打开底层新增节点菜单。
- 前端构建、缩放/来源关联测试、3D状态/连接/项目迁移测试及11项Python测试通过。实际页面验收记录在 `.cache/native3d/high-analysis/verification.json`。

## 后续质量门

优先用高模AO+高模分区建议识别凹槽。下一步需要从该证据选择连续、稳定的结构边界，再映射到低模；必须处理投射不支持面、跨薄壁误映射、碎片清理、背面一致性，最后结合少岛/拉伸/占用率要求验证UV。不能因为高模细节更多就自动接受更多切缝。
