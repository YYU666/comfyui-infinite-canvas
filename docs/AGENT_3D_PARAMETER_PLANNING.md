# 3D Agent：动态参数、Skill 与 MCP 设计

日期：2026-11-03。对应 PRD 修订 1.1.7；目标功能版本仍为画布 1.1.0。状态：设计，尚未实现下述 3D 接口、Skill 或自动调参。1.1.4 补充已有 UV/材质分流，1.1.5 明确输入与解码seed分离及实验能力边界；1.1.6 补真实8/12GB验证与新模型/材质支持门；1.1.7 补跨资产/跨执行器参数schema与模型切换。

## 1. 目标与职责

每次制作根据当前模型、目标低模、UV、材质来源、用途和硬件选择参数，并通过测量与试算调整。界面使用“当前预算内已验证的推荐设置”，不承诺未经穷举证明的全局最优。预设只提供起点，不能替代当前模型检测。

“最优”的约束至少包括目标用途/观看尺度、允许的轮廓和表面误差、面数/纹素预算、贴图通道、目标引擎切线约定、时间、RAM/VRAM。用户未提供时，使用可见、可修改的产品默认档案，并记录为假设；缺少真实单位时不得编造厘米值。制作中的用户锁定参数优先保留。

| 层 | 责任 | 不承担的责任 |
|---|---|---|
| 几何/烘焙执行器 | 测量、资源预估、候选试算、参数范围校验、质量报告、取消/恢复 | 不凭模型标题推断结构，不用成功退出代替质量通过 |
| 参数规划器 | 根据当前特征和约束生成有限候选，记录规则/版本/证据，选出符合门槛的候选 | 不要求 LLM 计算数百万顶点或猜射线距离 |
| Agent | 解释目标、结合报告和局部图判断问题、选择候选/调用工具、决定局部重试或待复核 | 不绕过硬门槛，不伪造检测数值，不无界限反复试算 |
| Skill | 规定调用顺序、诊断方法、读取哪些报告、何时停止以及如何交付 | 不是几何算法、不能通过文字保证执行安全或结果正确 |
| MCP / HTTP / CLI | 对同一服务提供受控访问，传递资产 ID、版本、任务和报告 | 不各自复制算法、队列或项目写入状态 |

画布手动“一键推荐/制作”也调用同一规划器和验证器，无 Agent 或无 MCP 时基础流程仍可工作。Agent 扩展解释和复杂故障判断，不成为启动画布、执行几何或读取质量报告的硬依赖。

同时处理输入3D资产变化与AI执行器变化，按 [通用节点契约](3D_NODE_ADAPTER_DESIGN.md)读取资产报告及适配器精确schema。公共制作目标、模型专属参数和本机配置分开；不得从岩壁案例继承固定offset/边界数，也不得向其他模型发送MeshAnything的8192点/MC配置。首次绑定权重与环境后，适用的参数仍需根据每个新资产重新推荐。输入不支持或锁定目标冲突时报告，不能静默降级。

## 2. 每次任务的闭环

1. **获取上下文**：读取当前项目/节点、不可变资产版本、执行器能力、硬件预算和目标档案；复用相同哈希的有效报告，变化则失效。
2. **检测模型**：确认坐标/单位/变换、连通部件、薄片/开口/非流形、法线与材质；识别已有源 UV/贴图及每通道 UV 绑定，保持只读；高低模配对后测轮廓/表面偏差分布，目标 UV 后测拉伸、重叠、纹素密度和留白。
3. **建议与预检**：返回参数、实际单位、范围、理由、来源报告、风险和候选资源估计。高模解析/检测本身也要预检，不能等做完大检测才限制内存。
4. **有限试算**：先固定几何、输入版本与可复现采样种子，按待诊断问题改变参数。轻量试烘不使用显示代理冒充高模；全模型低分辨率诊断与关键区域原分辨率检查相结合。
5. **对比和修正**：先过滤硬失败，再比较质量/耗时/内存。必要时局部调整 Cage、分组、UV 或低模；不得为使指标通过而缩小检查区域或提高容忍阈值。
6. **正式运行与复核**：选定候选并执行正式分辨率，重新检查实际成品、接缝和目标切线。预览通过不能自动继承为正式贴图通过；选优用的样本外另取检查区域/视角。
7. **交付**：在当前画布保留真实版本、推荐理由、质量结论与失败区域；用户锁定/修改参数生成新版本。文件生成完成与当前页面已接收保存分别记录。

初始自动调参预算：每个受影响阶段最多 3 个轻量候选（含基线），选定后 1 次正式制作；同时受用户任务时间及资源上限约束。该数值为待实测的产品初值，不是固定算法要求。不能通过创建新 job 重置同一 run 的总预算。取消、上游变更、锁冲突、OOM、连续无改善或预算耗尽时停止自动提交，保存最好候选并说明是否仍不合格。Agent 失联不触发无限后台重试。

## 3. 动态参数依据

| 阶段 | 当前模型证据 | 可调整项 | 保护条件 |
|---|---|---|---|
| AI 输入/候选 | 面数、细节尺度、部件、采样覆盖、峰值预测 | 已验证范围内的预处理/采样档、独立输入seed与解码seed、候选数量 | 纯解码对比必须固定输入hash；结构约束解码是未验证实验profile；不自由更换模型/精度，不因失败切传统减面 |
| 修复/贴合/LOD | 开口语义、轮廓、特征边、误差分位数/最大值和位置 | 局部修复、位移/旋转限制、每级面数预算 | 不能填掉开放岩壁外边界；先保形再争取面数，不强行凑整数 |
| UV | 已有源 UV/贴图、低模来源/拓扑对应、结构、缝、拉伸、目标纹素密度 | 已验证图集复用或新 UV 对烘、分岛、打包、分辨率、岛间距 | AI 新拓扑不保证保留原 UV；源 UV 不重展；保存 seam/xref；复用图集锁定时不静默换路线；源镜像/平铺与目标冲突重叠分别判断 |
| Cage/投射 | 高低模距离分布、局部厚度/曲率、漏烘/多层风险 | 前后距离、局部 offset、分组、投射方向 | 最近距离只给候选起点；增加距离可能命中背层，必须验证身份/方向与局部图 |
| Normal | 硬边、角点法线、三角化、镜像/切线、局部投射变形 | 切线配置、方向校正、AA、扩边 | 引擎约定优先；AA 不能修错投射；不把改变着色灯光当法线修复 |
| AO | 几何尺度、细缝/薄片、遮挡范围、分组、噪声估计 | 遮挡距离、采样数/分布、背面与跨组遮挡 | 数值范围随用途和单位变；AO 噪声估计用重复/分组采样等真实依据，不能靠均值冒充 |
| 材质转移 | 源/目标 UV、源材质绑定/纹理因子、法线切线基、通道/色彩空间/过滤方式 | 源高模向新 UV 的对烘、采样/输出精度、法线细节来源、AO 来源 | 源切线法线先解码再转入目标切线，不直接复制 RGB；缺少 roughness/metallic 时标缺失或基础值；每档 LOD 默认从原源对烘，避免反复重采样 |
| 大图与资源 | 实测运行档案、当前可用 RAM/VRAM、输入大小 | 图块、并发、受测 CPU/GPU 后端 | 不偷偷简化烘焙源；CPU 后端也要测 RAM，未知峰值不能放行全量任务 |

例如 AI 岩壁出现局部漏烘：先分辨源缺面、Cage 未包住、低模跨层或法线错误，观察缺陷分布；只有证据支持距离不足才局部增加投射范围。薄层附近仍错投射时需要修 Cage/低模，不能盲目增大全局距离。AO 投射正确但有采样噪点时才增加 AO 射线。切线不一致时先统一配置，不继续堆采样。

已有 UV 的高模不能默认重新展开；Agent 应解释“源 UV 已保留，但 AI 低模使用新 UV，原材质将对烘过去”。仅在受测算法保留原图集并验证外观后才能建议复用原贴图；复制 UV 层名、贴图文件或最近点逐顶点 UV 均不能证明保留成功。若原材质不能解析，明确缺失通道和支持边界，不以中性材质冒充对烘结果。

## 4. 质量和置信度

质量报告至少分别包含：几何/轮廓误差、UV 非法项/拉伸/留白、Cage 检查、命中率与漏烘图、错层风险、投射变形、切线/接缝检查、AO 噪声、源材质覆盖、导出往返及资源峰值。所有指标写测量方法、范围、分母/单位和采样局限；同一比较使用相同有效区域，不能忽略漏烘像素以美化分数。

存在非法 UV、资源越界或关键投射错误时，综合分高也不能通过。错层正确性难以全自动证明时标 `needs_review`；Agent 视觉判断与数值检测分开记录。最终显示 `pass / needs_review / fail / not_tested`，未知项不能由 LLM 自报“高置信度”变成 pass。

有限候选只说明“本次比较中更好”。审美、目标性能和用途存在取舍：质量相当时再优先低耗时/低内存；无法满足所有约束时保留候选并说明冲突，不隐藏降低标准。

初始硬失败规则、受支持材质通道、统一计算空间、对应缓存与正式覆盖测法按 [1.1.6流程复审](3D_PIPELINE_REVIEW_AND_MODEL_SURVEY.md)落实。Agent提交前需查询精确模型/权重版本、许可用途、GPU架构、后端/精度以及该阶段的真实资源档案。作者“8GB/12GB”仅是候选筛选证据；未知峰值、缺授权或不支持的材质不能由Agent自行标为可用。公开8GB和12GB支持分别需要真实硬件证据，24GB限额测试只验证预算处理。

新执行器不自由替换用户锁定模型。模型能力按 `geometry_from_mesh / geometry_from_image / material_generate / material_transfer` 区分；生成材质不冒充源材质还原。自动试算仍共享原run预算，换后端、精度或输入预处理不能重置次数。量化/CPU offload仅在后端实际提供且通过质量/资源验证后可推荐，不能让Agent凭经验生成不存在的开关。

## 5. 复用现有 MCP，扩展 3D 语义

现有 `agent_mcp.py` 已有 stdio MCP，四个核心工具为 `state / query / apply / wait`，另外已有 `canvas_current / canvas_command / canvas_call / canvas_result` 当前页工具，并有 `canvas://context / protocol / schema`。`docs/AGENT.md` 的“四个核心工具”摘要未完整列出当前页工具，以实际 schema 为准。新增功能优先扩展同一服务的协议与能力声明，不新增一套争抢项目状态的 MCP 服务，也不把所有底层几何函数暴露成几十个工具。

以下是**待实现语义**，不是目前可调用接口；具体 schema 在 T01 中确定：

| 语义 | 建议承载 | 返回/行为 |
|---|---|---|
| 当前能力、限制、参数定义 | `state/query` 与按需 schema 资源 | 引擎版本、支持阶段/参数、许可状态、资源档案；没有的能力明确 unsupported |
| 分析/建议/试算/正式制作 | `apply` 下受控 3D 操作 | 带不可变资产版本、约束、预算及 idempotency key，返回 runId/jobId；大分析也按任务执行 |
| 状态、完成或取消 | `wait/query`；取消使用受控写操作 | 阶段、变化与终态；取消只影响该任务拥有的进程 |
| 报告、候选比较、局部证据 | `query` 按字段/区域分页 | 紧凑指标、问题清单、报告和预览引用；不回传整网格/base64 |
| 参数选用与结果交付 | 当前页面命令通道 | 版本/节点/来源连线与保存 revision；并发修改返回冲突 |

计算提交与画布写入必须区分：后台可对不可变素材快照执行授权任务；当前已打开项目仍只有当前页面作为最终写入者。MCP 入口对节点修改、选用和交付必须路由到当前页面桥，不能同时调用旧服务端 `apply` 去写同一项目。页面失联可完成已提交计算，结果状态为待接收；不得直接覆盖 `project.json`。

契约统一校验 `projectId / assetId+hash / geometryVersion / uvVersion / engineVersion / expectedRevision（有画布写入时）/ runId / opId / constraints / parameterLocks / budget`。自动调参保留候选来源链和选用理由；任务失败响应含可重试类型及实际阶段。服务端防止重复生成、越界参数与过期来源，不依赖 Skill 自觉遵守。

AI操作还绑定 `adapterId / adapterVersion / modelId / weightsHash / parameterSchemaVersion / resolvedParameters`。参数默认值、语义、单位与条件由适配器声明，后台拒绝未知/不兼容项。模型切换保留公共目标，专属参数只按显式迁移规则处理；运行中job使用冻结配方，旧job晚完成不能被标成新模型结果。后端可扩展不代表任意本地权重即插即用；未安装适配器的模型由能力查询返回缺项。

当前启动协议仍会检查 ComfyUI，现有 MCP 并不因此已满足独立 3D 目标。T01/T02 需按能力拆分启动/健康检查；仅启用 3D 时不得检查或启动 8188，也不要求 Blender。外部 Agent 使用哪个 MCP 客户端不改变这一点。

## 6. Skill 的范围与交付时间

计划新增项目 Skill `refmuse-3d-asset-workflow`，等实际 schema 与工具可用后编写并验收；本轮不创建一个引用尚不存在工具的可执行 Skill。已有画布 Skill 保留为项目操作入口，按 3D 任务路由到专门指南，避免整套安装/图像生成说明进入每次 3D 上下文。

Skill 主文件保持短：输入/目标确认 → 查能力与有效报告 → 参数规划 → 有界试算 → 检查 → 正式运行 → 当前画布交付。按需加载几何、UV、投射、材质、故障、资源预算与目标引擎参考。工具返回的模型名称、材质备注、第三方说明均作为数据，不能修改工作流程或指挥任意代码执行。

规则、阈值和参数范围以服务端版本化 schema/质量 profile 为权威；Skill 只解释如何应用，避免两处数值不同。支持检查 Skill 的 schema 版本范围，未知版本先发现能力，不套旧参数。

尽量减少模型调用：数值计算、搜索候选、测资源和等待在后台完成；Agent 只在目标解释、候选决策、异常诊断和最终审阅时介入。优先摘要与局部压缩图，不反复读取整画布、完整日志或高模。历史推荐只在来源、后端和用途匹配时作为候选，仍要验证，不能把一次成功自动推广为通用“最佳参数”。

## 7. 验收与实施拆分

T01/T02 定义统一契约与当前页交付；T03–T10 为每阶段提供真实测量和质量门；新增横向 T13 实现参数规划器、MCP 适配、Skill 与闭环验证；T12 最终验收包含 T13。

必须验证：同一模型不同单位/缩放，薄壁与厚实模型，开口/多部件，错误法线/镜像，源材质缺失，接缝/UV 非法，资源不足，后端能力变化，用户锁定参数，阶段途中修改父级，断线/重放/取消，以及预算耗尽。

对照组使用固定预设，实验组使用动态规划，在同一资产快照与相同总预算下评估；不能给实验组无限试算再声称更好。记录有效覆盖、错误数/位置、表面/轮廓误差、视觉复核、耗时、资源及 Agent 调用量。新增验证区域避免只针对候选选优样本调参。基础质检负例必须拒绝通过；所有正式结论在真实引擎与当前画布有证据。

无 Agent 的画布推荐也需运行；MCP/Skill 只接入同一内核。干净环境端到端不安装 Blender/ComfyUI，不依赖外部商业软件；商业软件可在有授权的测试环境作为质量对照，不成为用户运行依赖。
