# 通用3D减面节点：资产分析、模型适配与参数配置

日期：2026-11-03。对应PRD修订1.1.8；功能目标仍为画布1.1.0。

接续约束：公共修复/贴合/连续LOD不可被单个AI执行器的直接低面输出替代。LOD每档绑定上一档实际结果哈希；FBX主要交换格式、结构切缝与规整UV、同机位阶段报告按PRD1.1.8验收。当前基础试用省略这些阶段的结果不算符合本设计。

状态：设计要求，尚未实现通用节点、注册表或新增AI后端。本文规定如何支持不同资产和不同算法，不表示任意权重下载后都能直接运行。

## 1. 两种“换模型”都必须支持

1. **更换输入3D资产**：不能依赖测试岩壁的文件路径、大小、面数、朝向、边界数量或材质。每个新资产先检测，再生成适用参数。
2. **更换AI模型/算法**：同一个“AI低模”节点选择兼容执行器及权重版本，输出统一低模资产，继续连接已有修复、LOD、UV和烘焙链。

测试岩壁仅是回归夹具。通用不等于所有输入都能自动通过：薄片、开放表面、多部件、角色、扫描噪声和已有材质等分别声明能力；不支持的输入提前提示，不能套测试案例的处理后标成功。

传统减面仍是用户明确选择的处理方式，单独标明算法身份；AI失败不自动切换。图像生高模与mesh/点云条件低模生成使用不同能力标识，不能把图片生成模型随意放进减面模型下拉框。

## 2. 节点界面与参数分层

右键菜单保留一个“AI低模”入口，节点显示输入资产、执行器/权重、目标、推荐参数摘要、实际结果面数与检查状态；模型名属于选择项，不为每个模型新增一个节点类型。下游UV、烘焙接口不依赖具体模型名。

| 层级 | 用户看到的内容 | 配置来源与规则 |
|---|---|---|
| 制作目标 | 目标三角面数/LOD档位、保形要求、保留部件/开口/硬边意图、源材质与UV策略、时间/资源预算 | 按资产与用途推荐，可修改/锁定；目标不是模型必然能完成的承诺 |
| 本资产分析 | 单位/尺寸、部件、开口、薄片、法线、源UV/材质、预计偏差与资源 | 由分析器测量，有报告及范围；不能靠文件名推断用途或由Agent猜数值 |
| 执行器选择 | 已安装且兼容的AI模型、权重版本、就绪状态；未就绪条目显示缺项 | 从受信任注册表发现能力，按输入和平台筛选；不能只扫描文件扩展名就视为可用 |
| 模型专属高级参数 | 仅当前版本支持的采样、点数、精度、解码、预处理等项 | 由适配器的schema动态展示，有范围、单位、帮助、默认依据、互斥关系；未支持参数不发送 |
| 本机环境 | 独立运行环境、权重路径、GPU、受测精度/注意力后端、资源档案 | 首次配置并复用；路径不作为工作流可移植内容，凭据不保存到节点或导出包 |

默认界面只露目标、模型选择和运行结果。高级参数保留给熟悉算法的用户；不能要求普通用户逐次填写MC分辨率、token预算或Torch配置。Agent与手动操作查询同一schema并调用同一验证器。

“保形优先/速度优先”等产品预设必须解析为具体参数与选择理由，并把解析后的值写入运行快照。不能把不同算法的 `steps`、`resolution` 或 `temperature` 因为名称相同而当作同一种参数。

## 3. 换输入资产时的通用分析与分流

流程：资源/格式预检 → 不可变导入快照 → 几何/UV/材质分析 → 输入与执行器适用性判定 → 参数建议 → 有界试算 → 标准质量门 → 制作结果。

| 资产特征 | 必须动态处理的内容 | 禁止的案例假设 |
|---|---|---|
| 尺寸/坐标不同 | 单位、归一化与逆变换、距离类参数 | 固定世界空间offset或默认单位为米 |
| 闭合实体/开放表面 | MC或直接表面采样的适用性、修洞范围、投射双面策略 | 遇开口一律封口或整体翻面 |
| 薄片/细缝/孔洞 | 检测最小特征尺度，识别可能被偏移/量化抹掉的结构 | 认为提高token预算就能恢复细节 |
| 多个部件/实例 | 保存部件身份和变换，能力允许时分别处理；连续表面需独立边界方案 | 只取最大部件，或无说明全合并 |
| 硬表面/有重要轮廓 | 测局部边界和轮廓误差，保形约束与后处理限幅 | 使用岩壁的平滑/补洞参数 |
| 已有UV/材质 | 源快照保护、通道支持预检、新低模UV与对烘 | 让AI输出冒充保留原UV或原材质 |
| 超大/扫描噪声资产 | 在解析、采样、BVH各阶段预估资源；清理作为独立派生记录 | 预览代理偷偷替代生产输入或源烘焙表面 |

首版支持范围仍以实际验证的静态道具/场景资产为准。若用户锁定的重要部件或孔洞不能由后端及质量检查保证，返回限制与待复核状态，不删除约束再继续。即使节点能连接，也不代表该模型已经适合此输入。

## 4. 执行器注册与提前配置

每个受支持模型族先开发并审核一个适配器。适配器可调用已安装的独立CLI/worker，仍须提供统一协议、退出/取消和结果校验；不接受节点直接提供任意shell或Python代码。

建议的三个配置层（均为待实现数据契约）：

- **模型定义**：adapterId/version、模型架构、权重身份/哈希/来源/许可、支持平台与输入/输出能力、参数schema及迁移版本。
- **本机绑定**：可执行环境、权重实际路径、设备与后端、安装/健康检查结果；只存本机配置，不能把测试机器路径写进官方节点。
- **运行配方**：不可变输入资产哈希、制作目标及锁定项、解析后的全部参数、后处理版本、资源策略与种子；任务运行后形成可追溯快照。

资源测量档案按适配器＋权重＋精度＋运行后端＋GPU型号/架构＋输入/输出规模绑定，不能只写“12GB可用”。能力与资源报告标记 `declared / locally_checked / benchmarked` 等证据层级；声明存在不自动等于本机验证通过。

首次使用执行器的准备顺序：

1. 校验模型定义与许可用途，检查所选输入能力；明确是否存在授权/权重缺项。
2. 在3D独立环境检查依赖、权重架构/哈希、GPU算子与参数组合；不得安装到ComfyUI或系统Python。
3. 读取或建立本机资源档案；未知资源只能标实验，按前述预算执行受控验证。健康检查不偷偷运行完整高模任务。
4. 根据当前资产生成参数预检结果；未满足依赖或必需参数时，列出具体缺项并禁止正式提交。
5. 固定执行配方，再提交实际任务。重复打开节点不重复安装、扫描全盘或加载权重。

已有适配器支持的新权重版本，经架构、schema、许可和输出回归检查后可能只需更新配置；全新模型架构通常需要新适配器与测试。不能承诺任意 `.pt/.safetensors` 放进目录就自动完成减面。参数schema不允许通过表达式、插件脚本或未知字段绕过后台校验。

## 5. 哪些参数确实需要模型专属配置

以下基于已核查能力说明差异，不把研究候选宣称为已集成；精确范围必须从选定版本代码/config核实，不能凭经验补造。

| 模型族 | 提前固定的配置 | 可以按资产或运行调整的内容 | 需要解释的限制 |
|---|---|---|---|
| MeshAnything V2 | 权重/架构、8192点输入约定、坐标编码、已验收精度/注意力适配 | 已验证预处理profile、独立输入seed/解码seed、贪心或采样策略等 | MC256不是通用安全设置；目标面数主要由后续LOD处理，改token预算不是精确控面 |
| BPT | 权重变体、对应tokenizer/config和运行依赖 | 适配器实际暴露且验证过的mesh输入、采样/解码项 | 不继承MeshAnything的点数、MC或解码配置；先核实具体源码再开放高级项 |
| TreeMeshGPT | 7bit/9bit对应的权重与配置成套选择 | 选定版本支持的生成/后处理参数 | 位数是模型变体，不是可以对同一权重任意修改的精度滑块；内置传统后处理须记录并避免与公共LOD重复执行 |
| MeshFlow（研究） | 权重/config、默认latent预算、受支持精度；可选图像条件另需DINOv3 | steps；启用图像条件时有效的guidance；权重config允许时num_verts | num_verts是大致顶点控制，不是精确三角面数；无图像时不显示有效guidance；许可门优先 |

同名“分辨率”必须注明是坐标量化、输入体素、latent数量还是贴图尺寸。适配器对每个参数记录：类型/枚举、有效范围、单位、默认值及来源、适用条件、是否影响资源/质量、是否可动态规划、是否需重加载、是否进入缓存键。未知或过期参数后台直接报错，不静默忽略。

模型内部已做的重建、清理、简化或归一化需记录步骤和实际输出；公共后处理读取这些标记来确定是否执行，但仍独立验证结果，不仅凭标记跳过QA。

## 6. 统一输入输出和换模型规则

上游交给适配器的是不可变源资产及处理快照引用；适配器自己生成符合该模型的采样/编码输入。未经确认不强制所有模型共享同一个8192点云或MC网格；做比较时记录必要的模型差异。

统一结果至少包含：输入源hash、assetId、adapter/model/weights身份、变换链、输出几何角色、实际面数/顶点数、原始候选、已执行后处理、能力/参数快照、耗时资源、质量与错误报告。无UV或材质的输出明确缺失，源材质始终沿来源关联供后续对烘。非三角输出若需三角化，保留原结果并创建有映射/参数记录的派生结果，不在读取时悄悄改写。

普通用户更换模型时：

1. 保留公共制作目标、输入源与已有结果；切换只改变下一次运行的配置。
2. 检查新模型的输入、平台、许可、参数与资源；显示可保留/需重新推荐/不支持的项目。
3. 专属参数按稳定adapter/schema身份分别保存；只迁移有显式规则、语义/单位兼容的项。用户锁定项冲突时停止该项执行，不能静默解锁。
4. 生成新配方后提交新run；运行中的旧job不热切模型。旧job完成仍归旧配方，不能覆盖新配置的结果。
5. 新结果通过标准质量门后，用户或已授权Agent选择为下游输入。下游仍连接同一个逻辑结果端口，实际输入版本明确变更；依赖旧候选的修复/贴合/LOD/UV/Cage/烘焙逐项按PRD依赖规则重新核验或标stale。即使拓扑相同，位置、法线或来源变化也不能自动继承旧质量结论。节点和连线可复用，历史制作成果保留，不自动重跑昂贵任务。

配置草稿未运行时，已有结果仍可查看，但显示“来自上次配置”；不能显示成新模型已经生成。新模型失败也不删除旧的可用结果。缓存包含源、变换、适配器/权重、参数、种子、预处理与后处理版本；不能跨模型借旧结果冒充本次运行。

更换输入高模同样使用草稿/冻结运行/历史结果分离：原候选始终关联原高模及其源UV/材质，不因节点当前输入变更就换掉烘焙来源。新输入重新生成资产报告和参数建议；单位、尺寸和来源相关的锁定项重新校验，冲突时不静默解锁。旧job晚完成仅进入原来源历史，不自动激活到新输入流程。选择新候选后再按依赖传播下游失效。

模型原生目标控制分 `none / approximate / exact`，并记录单位是面还是顶点、适用条件及证据。制作目标与原生控制分别展示：后处理可以尝试达到目标面数，但受保形约束时报告实际面数，不伪称神经模型已经精确完成。

## 7. Agent与手动用户共用能力

现有MCP/HTTP/CLI的能力查询返回执行器清单、精确schema、支持输入、准备状态、参数限制和可执行的受控准备操作。Agent先读当前资产报告，再查询选中适配器；不使用模型名称硬编码一套参数，也不把历史案例配置无条件搬给新资产。

所有建议必须由服务端schema验证；未实现字段不能靠自然语言提示词让后端执行。用户选择“比较模型”时，在共同run预算内创建有限候选；不可因换模型重置试算次数，也不能比较不同面数后直接宣称质量更强。更换模型必须在授权候选范围内，遵守已有参数锁定与许可/资源门。

无Agent用户同样可点“推荐参数”“检查环境”“生成”“比较结果”。环境缺失说明给出具体组件与准备入口，不能只显示“生成失败”。运行与当前画布写入仍分别通过任务服务及当前页面桥完成。

## 8. 实施与验收

沿用原任务图：T01定义注册表/版本schema/能力；T02隔离runner与持久化；T03提供通用资产分析；T05实现适配器协议和真实后端；T06–T11消费标准结果；T13提供动态建议与MCP；T12做跨资产/跨模型验收。

T05的阶段验收到真实候选、统一协议与参数/环境处理，不等待尚未开发的UV/烘焙。第二真实后端可在几何链就绪后并行接入；双后端完整链验收归T12/M4，在T06–T11完成后执行，避免任务依赖形成循环。

通用性的必要验收：

- **跨资产**：至少闭合有机形状、带孔硬表面、开放场景块面、带源UV/材质的道具四类；受支持类走完整链，不支持类准确拒绝/复核。禁止按测试文件名或固定边界数量分支；尺寸/朝向变换夹具独立验证。
- **跨后端契约**：用两个不同schema的测试适配器覆盖发现、参数、结果、取消、迁移与错误，证明节点/下游无需写死模型名。测试替身只能证明协议，不证明AI兼容。
- **真实换模型**：至少两个许可/环境允许的真实AI后端，针对同一受支持源资产分别完成生成→修复/LOD→UV→源材质烘焙→导出。记录实际后端、原始结果、后处理与完整质量报告。若仅一个真实后端可用，标“可扩展架构＋单后端已验证”，不能宣称已验证跨模型全流程；第二后端作为独立验收项保持未完成。
- **参数错误**：未知字段、范围越界、单位错误、7bit权重配9bit配置、不存在注意力实现、精确控面不支持、锁定项冲突均在计算前失败。
- **切换与恢复**：运行中改配置、切换权重、旧job晚完成、切回旧模型、适配器升级/缺失、复制节点与跨机器打开项目；旧成果可看，未知模型只阻止新计算，不能损坏项目。
- **资源与可靠性**：8/12GB仍按真实硬件分档验收；准备检查不隐式加载多套大模型，取消后回收当前worker资源；重放不会重复安装或计算。
- **用户交付**：每个真实候选在当前画布可见、有来源连线和保存revision；统一节点展示真实执行器及输入/输出版本，无需用户重建整条UV/烘焙流程。

本轮接受的是通用节点契约与参数配置计划；尚未把任何候选安装成画布节点。参考：[总PRD](PRD_3D_ASSET_WORKFLOW.md)、[Agent参数规划](AGENT_3D_PARAMETER_PLANNING.md)、[模型核查与低显存计划](3D_PIPELINE_REVIEW_AND_MODEL_SURVEY.md)。
