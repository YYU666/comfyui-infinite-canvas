# 画布基础视频编辑与长视频处理方案

文档版本：0.1.0。日期：2026-11-10。状态：调研与产品方案，尚未实现或部署；不是发布版本号。

## 1. 目标与使用方式

在当前画布增加独立的「视频编辑」节点。用户把视频接入节点，点击「编辑视频」或双击预览，在同一页面的编辑面板内完成素材裁切、分割、排序、原声处理、区间 AI 处理及最终导出。关闭面板回到原画布，节点内展示最终视频，不额外堆叠重复结果节点。

基础剪辑和导出由画布后端执行，使用现有 FFmpeg/PyAV 能力，不需要 ComfyUI 或 Agent 在线。AI 处理通过独立引擎适配器调用 ComfyUI，Agent 可辅助规划、写提示词和审片，但不承担正常操作才能完成的隐藏步骤。

首版完成「导入 → 编辑 → 预览 → 导出」的闭环，并为后续四人换装长视频保留明确接口。先提供一种视频主轨和绑定原声轨，不同时制作完整多轨专业剪辑软件。

### 2.1 时间线导演台：最值得参考的是交互与编排

[Songssx/ComfyUI-MiniMaxH3-TimelineDirector](https://github.com/Songssx/ComfyUI-MiniMaxH3-TimelineDirector)，固定 commit `050226d37d25e20d878b47bdf92c8f912afccdaa`。

已核实：

- 多视频素材移动、拖动首尾裁切、播放头分割、删除、吸附及数值定位。
- 低清代理预览，视频原声随片段移动、裁切，支持原声锁定。
- 多个 GEN 生成选区、按段分配图片和音频、保存全局/分段提示词。
- 长视频通过有限分段生成、Latent 尾部延续、重叠去除及音画合并实现。
- 二采可保留低清和高清两层上下文；这是该引擎的实现，不应直接作为所有引擎的统一算法。
- `js/minimax_h3_timeline_director.js` 中有实际时间线状态、split 操作、裁切与播放时间映射；不是只有说明文字。
- 低内存版本逐段解码、编码到临时视频后合并；`segment_video_sampler.py` 存在该落盘实现。

关键限制：README 明确低内存版本「不保存 Latent，也不提供片段重跑」。其临时成品在生命周期结束或异常清理中删除；不能直接满足画布需要的持久断点恢复。它的预设也不记录模型、插件、ComfyUI 版本，画布需另存可复现配方。

其「无限时长」指受资源约束的逐段生成，不是模型一次无限上下文，也不证明人物始终稳定。README 所列直接生成案例为 52.625 秒，文件名称带 60s；不能只看文件名当作完整一分钟。没有在本机运行或验收这些样例。

### 2.2 动作迁移 Skill：适合参考批处理和区间重试

[wjc573/h3-motion-transfer](https://github.com/wjc573/h3-motion-transfer)，固定 commit `1991f646ca4dcca5d90943b17c3740694e26b4e7`，Skill 标记 v4.1.0。

作者教程所链接飞书页面直接提供此仓库。它不是剪辑器：要求用户先切好文件，以 `1.mp4`、`2.mp4` 表示独立镜头，`3-1.mp4`、`3-2.mp4` 表示同镜头续段。脚本根据命名选择上下文，串行运行，持久化任务状态，拼接成片，生成源片/结果对照和验收报告。

工作流 JSON 已核实为 93 节点，保存于仓库 assets。它使用 Ref2VA 路线和人物替换 V1.5，但当前模板还包含 Dasiwa 混合基础模型、多个 Turbo 适配器、TemporalWindow、Spark、Spectrum、SelfLift-Split 与 latent upscaler。不能把它简化成「我们现有 V1.5 同参数就能复现」，也不能默认所有插件和模型已安装。

上下文图取上一段结果尾部 22 帧，加入 Guide、补齐参考长度，再裁去生成前缀。作者文档特别指出参考帧数与生成长度不匹配会导致动作节奏错位；这是一条重要的待实测假设，不能据此声称此前跳动只有这一种根因。图中确有长度表达式、补帧、Guide 和输出切片节点。

需要改造的地方：

- UI 用镜头组和「继承上一段」选项代替要求用户靠文件命名表达依赖。
- 不按最近任意一次成功的 ComfyUI 历史自动认领生产模板；需要显式工作流指纹和兼容验证。
- 不沿用未用图片槽里的示例素材；素材槽及其引用标签由选区显式映射。
- 不能用进程退出冒充任务取消，更不能用全局 `/interrupt` 中断其他画布任务。
- 提示词 lint 属于结构校验，不能拿固定措辞或长度规则当作绝对画质门槛。可预览质量警告，只阻止无效参数/素材等技术错误。
- 作者关于多视图整图无需裁切的建议，与本机已查明的参考被缩小风险不一致；画布必须保留可配置的参考准备策略，实际比较后再固定。

### 2.3 1080p 与资源约束

[SelfLift-Split](https://github.com/wjc573/ComfyUI-SelfLift-Split) commit `7a0bbc7d37675674426341702940bbfddfe2602a`，通过低分 Euler 采样 → Latent 放大 → 共享 sigma 边界续采实现高清输出。源码/文档明确二采使用 `DisableNoise`，再次接随机噪声是错误接法。

配合 [TemporalWindow](https://github.com/mo-akkakk/ComfyUI-MiniMaxH3-TemporalWindow-SpatialTiles) commit `a7755d0cd24033e4f4189f16c7e96b7891896f02` 可以时间分窗，但初始参考编码、外置放大与最终解码仍可能处理整段，不能称全流程恒定内存。

第二套工作流的目标是约 2.0 MP、按原比例并对齐 32 的尺寸；文档例子为竖屏 1056×1856，并非严格 1080×1920。产品必须区分生成尺寸与最终封装尺寸，导出「1080p」需显示实际宽高及缩放策略。

作者给出的 RunningHub 单段建议 6.5 秒主要受平台约 40 分钟任务限制影响，不是所有本地模型共同的时长限制。云端速度、费用、B200 或 5090 数据都不是本机 3090 Ti 实测。

### 2.4 与 Viggle Remake 的关系

上一轮已核实的 [Viggle Remake](https://huggingface.co/Viggle/Viggle-Remake) 更适合继续验证多人同场关键帧方案。编辑器应统一编辑数据与任务状态，保留独立引擎适配器：

| 引擎 | 身份/外观输入 | 连续性方式 | 配方隔离 |
|---|---|---|---|
| Remake swap | 已编辑的同场关键帧及 pins | 同镜头继承 17 帧生成前缀 | 专用 FL2VA 派生模型、六步 sigmas |
| h3-motion-transfer 示例 | 角色参考图和逐段提示词 | 图中 22 帧 Guide、补齐和切片 | Ref2VA 混合模型与适配器、双采和加速节点 |
| TimelineDirector | 按时间线分配的参考和分段提示词 | 可变重叠、Latent 尾部及 Drift-Control | 按其有限分段规划和节点契约 |

17 帧、22 帧、39 帧不能统一为一个全局硬编码。切镜处的独立生成也不能错误继承上一机位的构图。编辑器首版不默认把三套生成策略串联。

## 3. 当前画布基础与缺口

本次只读检查 `src/App.jsx`、`src/CanvasWorkbench.jsx`、`src/workbench-api.js` 与 `delivery_export.py`：

- 已有视频导入、视频素材/结果预览、ComfyUI 工作流构造、任务状态与项目保存机制。
- `buildCharacterSwapWorkflow` 现有图是短片单人处理，不能将它改一个时长值就当作完整长片四人编辑。
- `delivery_export.py` 提供选中 Take 的素材交付、缩略图、清单等，不是帧精确时间线剪辑和成片合并引擎。
- 当前 App 入口是画布/旧工作台，没有本方案需要的独立视频时间线编辑面板。

不重复造素材存储、队列通知、项目锁和当前页桥；新模块应接入这些既有能力。

## 4. 首版用户流程

1. 在素材视频上点「编辑视频」，或从节点库放入「视频编辑」后连接一个或多个视频。只创建一个编辑节点。
2. 双击节点/点编辑，打开同页的大面板：左侧素材列表，中间预览，下方时间线，右侧所选片段设置。
3. 拖动首尾裁短；播放头处点「分割」；拖动片段调整顺序；删除可撤销；支持输入精确入点、出点、起点。
4. 原声默认和视频绑定。裁切、移动、排序同时作用于原声；用户可选原声/静音及音量。首版不自动生成或替换原音乐。
5. 可先播放编辑代理，确认成片时长与拼接顺序；无需提交 AI。
6. 选中区间后可创建 AI 处理草稿：明确要处理的演员、参考图、引擎、参数及依赖。按钮区分「生成选区」「继续任务」「重做本段」。生成全片是明确操作，不因打开编辑器自动触发。
7. AI 段完成立即在时间线上可播放；失败保留原片作对照但显著标记未完成，不把原片静默算作替换结果。
8. 导出前显示范围、有效生成段数、未完成区间、分辨率、帧率与声音来源。用户可明确选择「诊断预览（允许原片填补）」；正式替换成片要求所有计划处理区间有选用结果。
9. 完成后编辑节点内替换最终播放器并显示通知/可关闭提示音。节点只放时长、状态、结果和少量入口；详细参数留在面板，不固定 4:3。

|---|---|---|
| E1 基础剪辑闭环 | 视频/现有画布素材导入；代理；单主轨；裁切、分割、排序、删除；吸附；逐帧查看；撤销/重做；保存恢复；原声/静音/音量；MP4 导出 | 无 ComfyUI/Agent 也可把两段素材裁切重排导出，重开项目编辑不丢 |

## 6. 数据契约与时间精度

建议独立模块与概念：`video-edit-document`（编辑数据）、`VideoEditorPanel`（UI）、`video-edit-jobs`（后台导出/预处理任务）、`video-generation-adapter`（引擎能力）。均为拟新增，不表示文件已存在。

核心数据：

```text
VideoEditDocument {
  schemaVersion, id, projectId, editRevision,
  timelineTimebase: {num, den}, outputProfile,
  assets: [{assetId, contentHash, sourceTimebase, durationPts, proxyId}],
  clips: [{id, assetId, sourceInPts, sourceOutPts, timelineStart,
           linkedAudio, muted, gain, selectedTakeId}],
  operations: [{id, clipIds, ownRange, contextRange, shotGroupId,
                engineId, recipeVersion, referenceBindings, promptVersion,
                seed, dependencyHashes, status, jobId, takes}],
  exportJobs: [{id, editRevision, state, artifactId}]
}
```

- 时间底层用整数刻度和有理数时基；UI 显示秒与帧。首版可以选择一种固定输出帧率，但不能用浮点秒作为唯一真源。
- 基础编辑不受 H3 `5+17n` 限制。AI 适配器在内部补齐/取得上下文，完成后裁回用户选区；UI 不偷偷移动剪辑点。
- 原片 29.97 或可变帧率必须按 PTS 重采样；不能只更改 fps 标签。先构建全局映射，再切段，防止小段独立取整造成整片漂移。
- `ownRange` 是最终占用时间；`contextRange` 是生成所需的额外上下文。拼接按 ownRange 覆盖，不能简单把所有含重叠的视频相加。
- 编辑变更可立即播放代理；最终精确逐帧图由后端按映射提供。不能把浏览器 `currentTime` 的近似定位当作帧精确导出证据。
- 改提示词、参考、seed 或上游 take 后按依赖哈希使相关结果过期。同镜头后续片段可能受影响，其他独立镜头保留；已生成版本不直接覆盖。
- 导出绑定 editRevision 快照，导出时继续编辑产生新 revision，旧任务不覆盖新版选择。

## 7. 后端与资源规划

- 非破坏剪辑，源素材不覆盖；代理和生成/导出中间件分开存放。用素材 ID 引用源文件，不复制完整视频到每个节点。
- FFmpeg/PyAV 分段读盘、受限缓存；不将三分钟视频、所有人 mask 和 RGB float 张量一起装进浏览器或 RAM。
- 代理懒生成并复用；时间线缩略图按窗口加载、合并请求。预览默认使用代理，最终导出用源素材/被选用的成品。
- 默认帧精确裁切和统一编码，不用关键帧 stream-copy 冒充任意帧切割。只有整段、编码参数和时基兼容时才考虑无重编码合并。
- 原声音轨从编辑时间线映射重建，按采样点裁切，避免重复拼接模型上下文的音频。唱跳任务默认不生成替代声音、不对人脸做 crossfade。
- 导出和代理属于独立后台任务，CPU FFmpeg 作为可用基线；硬件编码按能力检测可选。GPU 推理共享现有队列，不能因视频任务停止其他线程生图。
- 持久任务保存完整配方、输入哈希和结果清单；检查点由工作台管理，不依赖 ComfyUI 临时目录保留。只保留恢复所需的尾部状态，完成后按明确保留策略清理。
- 缓存盘可配置并检查可用空间，不默认占满系统盘；活跃任务、被引用产物、源文件不得被临时清理任务删除。
- 进度分成准备/参考编码/采样/解码/合成/写文件，显示分项耗时。首段实测后再估算剩余时间；不直接套外部显卡分钟数。

## 8. 安全、保存与现有画布交付

- 用户当前侧栏仍是唯一项目写入端，面板是同页组件，不新开可写画布或 iframe 修改另一份项目。
- 后台 job 可以计算并登记独立作业结果；项目编辑与最终画布结果仍通过当前页面 revision/桥保存，不直接改 `project.json`。
- 页面不在线时标记「后台计算完成，待画布同步」，重连后幂等导入。不能把后台落盘称为已经在画布交付。
- 控件使用独立拖动区和 pointer capture；处理 pointerup/cancel/失焦，避免视频裁切拖动把画布永久锁为拖动状态。删除快捷键只作用于当前聚焦编辑器。
- 后端只接受项目授权素材 ID 和白名单参数；不接受任意本地路径、任意 URL、FFmpeg filter 文本或 shell 命令。子进程用参数数组，不使用 shell 拼接。
- 取消按 job/promptId 精确限定；不调用全局中断来取消本任务外的生成。

## 9. 引入第三方的方式

TimelineDirector 为 GPL-3.0；本项目不能在未审查分发方式时直接复制其前端/后端源码。可参考交互概念独立实现，或者作为用户安装的 ComfyUI 节点通过接口调用；集成分发仍需单独核许可。

h3-motion-transfer 仓库标 MIT，但依赖工作流、模型和插件各自许可独立。SelfLift-Split 本次 GitHub 元数据未给出明确根许可证，README 仅要求遵守上游声明，需核清才可复制/再分发。Viggle Remake 代码 Apache-2.0，权重仍受 H3 Community License 约束。

本次下载的 SKILL.md 作为第三方资料审查，未安装/启用为当前 Agent 指令，也未执行其自动上传、并发助手、默认删除或取消行为。画布应提供正常 UI 和确定性调度；Skill 只补充可选的创作分析能力。

## 10. 验收清单与开发顺序

1. E1：用合成测试视频（帧号/时间码/音频标记）验证非关键帧裁切、分割排序、撤销重做和保存重开；覆盖有声/无声、29.97 与 24 fps、不同比例。导出不重复或漏帧，音画对齐目标不超过一个输出帧。
2. E1 UI：原素材不变；节点只显示一个最终结果；双击编辑与预览可用；拖动裁切后画布仍能正常拖节点与保存。
3. E2：先做一段试生成，保留已批准演员映射。能选版本、只重做本段、修改参数后标明过期；质量警告可以人工接受，技术错误明确定位。
4. E3：制造中断/刷新/重启，确认完成段复用、运行任务对账、重复提交幂等；修改同镜头前段后只重算相应依赖后缀。
5. 长片：按实际 195.84 秒素材做代表短段后再扩展，核查全片覆盖、切点、人物映射、声音及缓存峰值。剪辑功能通过不等于四人生成质量通过。

决策：接受「先基础编辑闭环，再区间 AI 和长片调度」的方向；借鉴时间线导演台的交互与低内存思想，借鉴动作迁移 Skill 的分段/重试/对照机制。当前交付为设计与来源核查，没有宣称节点已开发完成，没有服务部署、模型下载或新生成。
