# 导入 PureRef 图片

从当前画布的添加菜单选择「导入 PureRef 图片」，或把一个 `.pur` 文件拖到当前画布。程序先在本机解析并显示缩略图、独立图片数量、合并重复次数与跳过的外链数量。确认导入后，所有图片先上传到当前项目，再统一加入画布并确认保存。完成的节点与普通图片素材相同，可继续连接电子主美、图生图或图片处理节点。

## 首版支持范围

- 读取 PureRef 容器版本 **2.1**、SQLite schema **200101** 中，被场景图片实例引用的内嵌资源（`source_type=1`）。本机 PureRef 2.0.3 保存的合成文件已验证此容器与 schema；应用版本号和容器版本号并不相同，不能据此保证任意 2.x 文件都支持。
- 支持可完整解码的静态 PNG、JPEG 和 WebP，保留 `.pur` 中的编码字节和透明通道，不重新压缩。动画和其他编码暂不支持。保存优化可能使 PureRef 内嵌内容不同于最初拖入 PureRef 的源文件；导入器只能提取实际内嵌内容。
- 同一资源的重复实例及编码字节完全相同的资源只创建一个节点，并显示合并次数。未被场景引用的旧资源不会导入。
- 图片按网格追加到现有节点右侧。**不恢复原布局、旋转、缩放、分组、裁剪、绘画、文字或注释**；导入原内嵌图，不是画板截图。
- 外链与非内嵌资源按实例计数并跳过，不访问其中的本地路径或网址。不会导入文件路径、原始文件名或场景元数据；图片使用 `PureRef-001.png` 等生成名称。只有外链、没有可导入图片时明确报错。
- PureRef 1.x 使用独立格式，当前明确不支持；不匹配的容器／schema、损坏文件和校验和失败都会停止，不生成空图片节点。

## 上限与错误恢复

首版每文件最多 64 MiB、图片资源表最多 128 项、场景图片实例最多 4096 项；每张编码图片最多 16 MiB，内嵌图片编码总量最多 48 MiB。单边不超过 16384 像素、单图不超过 2400 万像素、资源总像素不超过 9600 万。超过上限可先在 PureRef 中拆分画板、移除不需要的图片并另存副本后重试。

解析和预览不会向项目写入图片。解析／上传阶段可以取消；取消可能等待当前本地素材上传结束，但不会添加半批节点。上传失败也不会发布部分节点。已上传的不可变素材可能暂时留在项目资产目录，不会删除去重共享素材。

全部节点加入后若最终保存响应失败，界面明确提示「保存尚未确认」，不会自动重复导入。请保留页面，用项目菜单重试保存，确认已有节点后再进行其他操作。导入期间项目切换和底层可写状态受保护；原 `.pur` 与现有画布节点不修改。

## 实现与验证边界

解析在本机完成，不需要云端模型或 API Key。文件内容不会作为 SQL、脚本或指令执行。SQLite 在内存中打开，采用 query-only、trusted_schema OFF、禁扩展、禁附加数据库、固定字段 SELECT、普通表检查、长度与查询步数／时间预算。只读取必要图片字段，不读取源路径、URL、笔记、HTML 或缩略图内容；图片经真实像素解码和尺寸检查。容器 MD5 只用于发现损坏，不代表文件可信。

实现依据公开格式事实独立编写，没有复制第三方解析实现或数据库 schema。参考：[PureRef 官方自动化](https://www.pureref.com/handbook/2.0/automation/)、[公开容器事实](https://github.com/Vacyyyy/pur-2-file-format/blob/main/FORMAT.md)。后者研究的是应用 2.1.3，本项目另用本机 2.0.3 原生合成文件验证了 PNG、JPEG、透明度与重复资源；这些含本机合成路径的原生文件不随源码发布。

回归使用新生成的合成容器，以及可选本地原生合成样本，覆盖版本、损坏、校验和、类型、外链、孤立资源、解码、上限、取消、切换、上传失败、保存未确认和真实后端导入／重开。没有读取用户画板或运行真实付费推理。
