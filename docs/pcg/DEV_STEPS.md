# PCG 插件开发步骤与门禁

日期：2026-11-17。M0/M1为已实现基线；木一已批准M2标准库自写路线。M2代码正在本地集成、独立审查和证据归档，最终接收由主线程决定。M3–M5未开始。

## 当前范围与执行方式

- 模式：Core Team execution。主线程负责目标、合同、任务图、文档、集成、独立质量门和回执；有界实现分别负责几何、Windows隔离与任务/资产。实现者不审签自己的安全实现，唯一收尾驱动为主线程。
- M2工作树：`pcg-plugin-m2/video-workbench`，分支`codex/pcg-plugin-m2`，基线M1提交`3962fbf3dfa1759755b487525c536d8e92c36048`。M1原始基线main为`7a468ab0e3bfac7010356a21752f4c988f022bfe`，M2叠加评审不扩大M1范围。
- 本轮仅M2：5任务入口（game_asset明确不可用）、18固定原子、自写几何/Field、受限worker、保存DAG、内容缓存/dirty、取消/预算、真实GLB/JSON及静态SVG。无新依赖、复制第三方实现或动态代码入口；逐文件来源见`pcg/SBOM.json`。
- 不访问正式画布/生成端点，不启停既有服务，不安装/下载，不使用用户素材。测试为合成内存/临时项目/独立受限进程。代码与文档不改冻结资产链。
- 只开叠加PR；不合并、tag、Release、部署。CI、独立review与正式验收必须单独留据，文档接口不代替测试结果。

## M0 / M1：保留基线

M0固定命名空间、描述版本、改动边界与后续门。M1交付共享描述、类型合同、受管元数据broker、固定诊断worker、身份/幂等/失败保留、只读预览及Agent工具闭环。M1诊断是进程分离，不是OS沙箱；旧geometry_stub继续明确不可运行。保留旧项目、版本及诊断接口，避免用M2值覆盖协议1语义。

M1历史验证记录只对应当时快照，不自动证明M2回归或当前CI。M2最新证据和剩余条件在`VALIDATION.md`及外部`RECEIPT_M2.md`记录。

## M2：受限几何闭环（已批准，集成验收中）

| 顺序 | 实现与检查 | 接收门 |
| --- | --- | --- |
| 1 合同/发现 | registry为唯一schema；5任务、18原子；真实用途/参数/端口/示例/错误；保留M1 | 未知版本/字段/类型拒绝；game_asset报M3_BRIDGE_UNAVAILABLE |
| 2 几何 | Mesh/PointSet/InstanceSet、typed Field/Selection/Image；同一evaluate驱动配方与原子 | 四seed真实不同且重复一致；索引/面积/单位/轴向有效；非固定组合图 |
| 3 OS边界 | Windows AppContainer零能力、只读代码/自有temp、stdio allowlist、child禁止、资源job | 实际私有文件读写/网络/子进程拒绝、环境清理、内存/CPU限制；不可用failclosed |
| 4 图与任务 | 保存DAG、身份/幂等、项目隔离内容键缓存、dirty预测/实际trace、取消/失败/过期 | 下游修改只重算依赖后代；本任务取消；旧run不覆盖新run；预算/崩溃/超时留据 |
| 5 资产 | 宿主独占原子发布GLB/JSON/静态SVG、hash与完整handle绑定、认证下载 | Corner UV/法线保持；实例共享原型；显式realize有预算；独立解码真实GLB |
| 6 集成 | MCP创建→设参→连线→预检→run→wait→read→verify→export/cancel、只读结果 | bounded readback≤64样本；schema/菜单/错误恢复同源；旧功能回归/构建 |
| 7 审查/PR | 独立安全/正确性审查，修复复测，本地通过后PR/CI | 本地与CI证据完整，无未解决接收阻塞；木一决定合并/发布 |

算法预算为60000顶点/100000三角形/10000点/10000实例、单值32MiB；依赖图256节点，缓存32MiB/256条，256保留任务/4个任务准入、1个几何执行/64MiB最终值。资源限制并不使任何任意程序安全；公开入口仍是固定操作和有界JSON。协议2几何仅Windows可用，不支持宿主保留可读图并拒绝运行。

M2已知边界：没有外部模型解析、既有资产桥、材质纹理完整交付、原型碰撞约束、实时3D视口或正式画布验收。InstanceSet检查使用保守AABB；实例父缩放限制均匀以保留正确性；SVG为采样静态预览。若实际隔离/质量门失败，保留错误而不是降级或替代输出。

## M3：既有资产链桥接（未开始）

先确认冻结快照的正式来源/哈希与允许修改范围，再独立桥PR。建立明确模型版本/输入输出映射、项目/哈希/过期检查、原质量门与导出验证。验收包括既有模型→PCG、PCG→资产处理、游戏导出的真实链路，保留实例预算、pivot/单位/材质/纹理。game_asset在此门前只能占位；不伪造accepted或用代理替代最终模型。

## M4：增量展示与反馈（未开始）

需要批准的展示接口和真实模型，才实现阶段事件/graphRevision、可展开内部DAG、完整代理快照、有限同拓扑/实例delta、旧run防串线、恢复、释放与性能采样。M2静态SVG和内容缓存不等于M4完成。验收记录p50/p95、传输、内存与关闭释放；预览不作正式导出。

## M5：审查与发布候选（未开始）

完成逐文件许可/依赖闭包、威胁边界与回归、获准维护窗口的正式画布验收、菜单审阅、CI/打包与独立审查，再由木一决定合并及发布。缺少模型质量、美术用途、许可、身份/哈希或用户验收任一证据，候选不得通过。

## 看板与开放决策

M0/M1为实现基线；M2已批准且正在集成验证，最终accept待主线程收齐证据；M3/M4/M5未开始。M3冻结快照来源/哈希与接口授权尚未解决，不阻止M2无桥范围。自写路线已经决定，不再列为开放决策。隔离已在本机合成夹具实际证明，但平台支持、完整回归、独立审查、CI及发布仍各自设门。范围变更由主线程裁剪，不扩大为任意脚本/插件加载或正式服务测试。
