# PCG 插件开发步骤与门禁

日期：2026-11-17。状态：已批准实施 M0、M1；M2–M5 仅计划。

## 范围、基线与执行方式

- 模式：Core Team execution。主线程负责合同定案、文档、集成、质量门及回执；有界实现分别负责后端合同与宿主/MCP；独立审查负责安全和验收缺口。唯一 harvest driver 为本线程。
- 工作目录：专用 `pcg-plugin-v1/video-workbench` worktree；分支 `codex/pcg-plugin-v1`，从干净 main `7a468ab0e3bfac7010356a21752f4c988f022bfe` 建立。初始 dirty=0，无需搬运其他工作树内容。
- 本轮目标：共享声明、受管资产、独立进程诊断、任务身份、只读预览、完整 agent 工具回路。几何算法和既有 3D 桥没有实现，不能称为可建模产品。
- 改动预算：新增 `pcg/` 数据合同、`pcg_*.py`、`src/pcg*` 及对应测试/手册；核心仅注册、路由、类型化连接和只读展示挂钩；打包/测试清单按需局部补齐。禁止重构历史工作流和冻结 3D 文件。
- 不访问或操作正式画布，不触碰现有生成服务，不启动或停止已有服务。测试仅临时目录、独立子进程及 mock；不用正式项目素材。
- 不增加软件依赖，不引入第三方实现代码。许可闭包当前为本项目代码与标准库；未来算法依赖须独立审定、锁定版本和许可证。
- 本轮不合并、不发版、不部署；本地通过后仅推送本分支并开独立 PR。

## M0：范围与基线定案（本轮）

目标与产出：本步骤表、固定基线、合同边界、开放决策与验收矩阵。

执行顺序：
1. 确认 main 与专用分支干净；记录基线，不从其他脏树复制文件。
2. 固定命名空间 `refmuse.pcg`、descriptor v1、独立 stdio worker；宿主不动态加载任意代码。
3. 固定 M1 两类能力：基础合同诊断可执行；几何占位节点可发现/创建/连接/读回，但预检与运行明确拒绝缺失执行器。
4. 只借鉴本仓库已有注册、任务和页面权限惯例，新增手册自足描述接口；本轮不复制第三方实现。
5. 记录冻结 1.1.45 的来源与桥接权限未定，作为 M3 阻塞；不阻止隔离的 M1 合同开发。

验收（对照 PLAN 11、12）：专用基线可复现；改动白名单明确；无禁止许可代码、无动态执行入口；开放决策不伪装成完成。

门禁：若需要冻结文件、未批准依赖、用户素材或正式实例才能实现，停止该切片并记录原因。

## M1：宿主最小合同（本轮）

目标与产出：共享 NodeDescriptor v1、类型合同、注册器、资产经纪、任务壳、独立 worker、只读预览、MCP 和 agent 手册。

执行顺序：
1. 在 `pcg/` 固定单一 JSON 注册表与协议：descriptorVersion、插件/操作版本、分类、参数 schema、类型化输入输出、预算、权限、readiness、示例与错误。
2. 声明 GeometryArtifact、InstanceSet、Field、Attribute/Selection：项目及内容身份、米制右手 Y-up、几何绑定和 Point/Face/Corner/Instance/Detail 域；Field 只允许有界类型 DAG，无脚本/表达式。
3. 后端实现 strict 校验与资产经纪：仅受管项目内文件、哈希校验、不可变身份、拒绝路径逃逸/链接/未知格式/跨项目。
4. 实现独立 stdio worker 空壳，仅固定合同诊断白名单；几何运行返回 `EXECUTOR_UNAVAILABLE`。不打开网络监听，不继承敏感环境，不调用其他执行服务。
5. 实现任务壳：project/node/revision/run/job/输入身份、幂等、preflight/run/wait/read/verify；失败保留任务，旧版本不覆盖新结果，超时与崩溃显式失败。
6. 核心只做插件注册及只读预览挂钩。UI、MCP、worker 读取同一描述，类型化边显示真实连接。预览只显示状态、进度和实际诊断，不生成假几何。
7. MCP 沿用创建→设参→连接→预检→运行→等待→读回→核验；每工具提供严格 schema、示例与恢复办法，拒绝只读/错误项目/失效版本。
8. 补 agent 手册、合同/安全/任务/UI mock 测试、打包文件清单；本地测试、独立审查、修复，再推送开 PR。

验收（PLAN 11 M1、12.2/12.3）：

| 合同/行为 | 必须提供的证据 |
| --- | --- |
| 单一描述 | UI/MCP/worker 同源；未知版本、字段、类型、参数和权限被拒绝 |
| 无依赖可读不可跑 | 几何占位可读；预检报告缺件，run 拒绝；不输出虚假模型 |
| 诊断闭环 | 合成请求通过独立进程产生真实报告；run/wait/read/verify 绑定同一身份 |
| 资产 | 临时夹具哈希、项目归属通过；路径逃逸、链接、跨项目被拒绝 |
| 字段/域 | Corner 不被当成 Point；几何上下文与值类型固定；禁止动态代码和循环 DAG |
| 并发/失败 | 不同任务隔离，幂等冲突拒绝，失败保留，等待有界，旧 revision 拒绝 |
| 宿主兼容 | 原有图像/视频/扩展回归与构建通过；不更改旧包格式与冻结模块 |
| 展示 | 只读预览桩与工具结果一致，无手操视口；本轮无正式画布验收声明 |

门禁：诊断成功只证明 M1；执行器、OS 隔离或 3D 桥未就绪均必须报告。独立进程不是安全沙箱，后续引入模型解析/几何实现前另验隔离。

## M2：受限几何闭环（后续，未实施）

目标：少量可组合原子操作与基础体/岩石/散布/组合配方，实际网格及实例结果。

顺序：木一决定精选许可兼容实现或自写 → 固定依赖闭包/锁文件/声明 → 验证资源与文件网络隔离 → 实现有界几何和 typed Field → 属性传播/确定性 → dirty 子图与缓存 → 合成夹具验证。

验收（PLAN 12.1/12.3/12.5）：4 个不同 seed 产生真实不同且确定性的有效几何；散布保留实例；显式 Corner/拓扑失效；18 个原子操作及最多 2 个按需扩展按批准范围发现；组合出非固定预设图；预算、取消、崩溃与局部重算有实测证据。

门禁：未批准算法路线/许可闭包/隔离则不开始；不以统计报告代替实际模型。

## M3：既有资产链桥接（后续，未实施）

目标：注册明确模型版本，接原资产检查与处理链，保留质量门和来源。

顺序：确认 1.1.45 冻结快照来源/哈希及允许改动范围 → 单独桥 PR → 输入/输出记录映射 → 过期/哈希/项目校验 → 原质量门 → 导出验证。

验收（PLAN 12.1）：既有模型→PCG、PCG→资产处理、游戏导出三条真实链路；不替换原结果版本、不跳过质量门；实例实体化显式有预算；独立导入器验证单位、pivot、材质和纹理。

门禁：冻结授权未给出时停留合同层；不得搬运脏树、伪造 accepted 或把代理当最终模型。

## M4：只读增量展示与 AI 反馈（后续，未实施）

目标：AI 建图实时可见，每有效步骤有可读回结果，固定机位预览，无需手操。

顺序：统一阶段事件与 graphRevision → 可展开内部 DAG/端口映射 → 完整代理快照 → 同拓扑与实例有限 delta → 旧 run 防串线与恢复快照 → 生命周期和释放 → 性能采样。

验收（PLAN 12.2/12.5）：所有真实边可见，工具与已保存图一致；每步有真实 bounds/counts/身份；末端修改不重算无关分支；预览不可用于正式导出；记录 p50/p95 延迟、传输和峰值内存，关闭后释放。重步骤显示实际等待，不伪造实时成功。

门禁：没有真实模型/批准展示桥就不宣称完成；本线程仍不得操作正式画布。

## M5：审查与发布候选（后续，未实施）

目标：许可、安全、兼容、游戏资产与用户验收证据完整。

顺序：精确依赖/第三方声明审查 → 威胁模型/边界测试 → 旧功能回归 → 指定线程在获准维护窗口做画布验收 → 菜单审阅 → CI/打包验证 → 独立审查 → 木一决定合并及发布。

验收（PLAN 12 全项）：实际文件与哈希/配方/输入身份绑定；质量、可复现性与美术用途通过；代理与最终交付分离；无禁止许可和动态代码入口；本地及 CI 通过，用户验收留据。

门禁：缺任一证据则候选未通过；本任务仅开 PR，合并、tag、Release 由木一决定。

## 开放决策与完成看板

1. 木一确认冻结 1.1.45 快照的正式来源/哈希，以及插件接入允许修改哪些文件/接口；本轮不生成该快照。
2. M1 后选择精选许可兼容的既有几何实现或全部自写；决定后才估定 M2 依赖和实现任务。
3. 后续执行器所需 OS 级隔离由独立测试证明；本轮固定诊断 worker 不代表已交付通用几何沙箱。

看板：M0 已定本轮范围（桥接与算法选择仍开放）；M1 代码与手册已完成本地验证及独立审查，待 PR 的 CI 结果；M2–M5 未开始。质量结论与实际测试、PR、文件清单写入外部 `RECEIPT.md`。
