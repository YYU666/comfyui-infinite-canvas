## 执行顺序与写入边界

1. **宿主合同与发现（主线程）**：扩展共享 descriptor，保留 M1 版本/诊断兼容；五个用户入口和18个原子操作、严格参数/端口、机器示例与错误；M3游戏资产入口明确未就绪。更新 MCP、只读结果链接和手册，不碰冻结模块。
2. **受限执行器（几何 lane）**：纯数据 Mesh/PointSet/InstanceSet、typed Field/Selection、18个固定原子操作；入口配方使用同一操作执行器；真实 GLB，实例共享原型，Corner UV/法线分离。先合成夹具，禁止未验证解析器。
3. **OS 边界（隔离 lane）**：验证本机可用的无网络、文件权限隔离和资源控制；受限进程只持有必要 IPC 句柄，清理环境；失败则几何 preflight 明确不可运行，不降级成普通进程冒充隔离。固定可信诊断不等于安全沙箱。
4. **任务与资产（运行时 lane）**：保存图 DAG 预检、身份/幂等、按依赖求值、内容键缓存与 dirty 读回、取消/崩溃/超时、项目隔离、原子发布真实资产和哈希；结果与 run 绑定。旧输出不被输入或代理替换。
5. **集成验证（主线程）**：四 seed 确定性差异、可组合非固定图、Corner/拓扑失效、实例保留与显式实体化、缓存局部重算、真实文件导出与独立解码检查、取消/崩溃/预算、文件网络拒绝、旧功能回归。
6. **独立审查与 PR**：独立 reviewer 查安全/正确性/证据，修正并复测；本地通过后推送，只开叠加 PR、跑 CI。未通过的条件写入回执，不宣称交付成功。

所有 lane 共用本任务 worktree，不各建未同步基线；严格互斥文件归属。主线程维护本步骤与合同；worker 只修改指定模块，不推送、不合并、不改权限策略。累计文件超过原预算或触及冻结模块时停止扩展、重新裁剪切片。

## 初始公共执行合同

- 共享 descriptor 保持 v1：`refmuse.pcg.shape/rock/scatter/compose/game_asset` 五入口；18个原子操作使用 `refmuse.pcg.<operation>`。`pcg/registry.json` 为唯一操作 schema 来源。
- 几何中间值是有界 JSON（Mesh/PointSet/InstanceSet），Field 和 Selection 绑定实际几何内容/拓扑/域。它们不是 M1 的已登记 GeometryArtifact；经宿主验证和发布后才产生资产凭据。
- 执行器 API：`evaluate(operation, parameters, inputs)` 返回命名输出字典；`validate_geometry(value)`、`summarize(value)`、`export_glb(value)`。具体模块内合同通过 lane 早期交接固定，再写运行时适配，不猜字段。
- 图执行在独立受限进程，宿主缓存按操作版本、规范化参数、显式输入内容/拓扑/属性摘要索引；不把项目 revision 放入纯计算缓存键。缓存以项目/宿主实例隔离，有明确容量。
- worker 不读项目目录或注册资产库；只通过有界 IPC 接收已批准数据。宿主独占受管输出写入，worker 不拿用户文件路径。
- read-back 返回 bounds/counts/属性域、确定性抽样（最多64项）、实际计算/缓存节点集合和资产/run身份。完整数组不进入 MCP 回答。
