# Refmuse 网页端开发计划

- 版本：v1.0
- 日期：2026-10-29
- 状态：规划稿，尚未进入实施
- 关联文档：`docs/REFMUSE_INTEGRATION_PLAN.md`、`Refmuse-网页端-下载与开源内容-开发计划-v1.0.md`
- 首要目标：先完成“搜索参考 → 导入 Refmuse 本地工作台”的真实闭环，再扩展下载页与开源内容中心

## 0. 前提与基线

产品名暂统一使用 **Refmuse**。沟通中出现 `refmse.cn`，已有网页端计划使用 `refmuse.cn`；M0 必须确认正式域名，并统一官网、API、深链、签名、CORS／PNA、SEO 和文档配置。

M0 首先确认线上实际部署分支、提交、环境变量、数据目录和回滚方式，并打基线 tag。不得把旧工作目录当作线上最新版，也不得在未确认部署基线前直接修改线上功能。

复用现有 Express／ES Module、账号、项目、收藏、作品广场、R2／S3、管理后台和 UI 主题体系。新增页面沿用现有“克制、留白、沉浸”的明暗主题，不另起设计系统。

## 1. 产品范围

网页端承担四项职责：

1. **参考发现**：图片／视频搜索、筛选、详情、来源与收藏。
2. **本地连接**：把参考安全地导入 Refmuse 本地工作台。
3. **本地版分发**：下载、安装、模型说明、版本与 FAQ。
4. **开源内容中心**：模板、提示词、节点包和项目模板的展示、审核与安装。

v1 不做付费商城、支付、订单、创作者分成，不做云端与本地项目实时同步，不默认上传本地私人素材。

## 2. 信息架构

以下 `/reference*` 是逻辑路由名称；M0 优先映射到现有“灵感参考”真实路由，避免重复建设两套参考页面。

```text
/reference                         参考搜索与发现
/reference/:id                     参考详情与本地导入
/favorites                         收藏夹（复用现有能力）
/library                           我的内容库（后续整合）

/local                             本地版下载页
/local/install/windows             Windows 安装
/local/install/macos               macOS 安装（按支持矩阵开放）
/local/models                      模型清单、来源与校验
/local/faq                         常见问题
/local/changelog                   版本记录

/open                              开源内容首页
/open/search                       搜索与筛选
/open/p/:slug                      内容详情
/open/c/:handle                    创作者页
/open/library                      已加入／已安装
/open/submit                       提交内容

/device                            本地设备授权（后续）
/admin/local/releases              本地版发布管理
/admin/open                        开源内容审核、举报与下架
```

导航调整：

- 桌面与移动导航增加“本地版”和“开源内容”。
- 首页增加“搜索参考”和“下载本地版”入口。
- 参考详情提供“导入 Refmuse 本地工作台”。
- 页脚补充本地版、模型说明、许可、隐私、内容政策和反馈入口。

## 3. 第一期：参考搜索与详情

### 3.1 搜索页

- 图片／视频统一搜索，支持关键词、类型、标签、来源和更新时间筛选。
- 卡片展示缩略图、标题、作者、类型、来源和收藏状态。
- 支持排序、分页或游标加载、空状态、错误重试和搜索条件分享。
- 视频卡片明确时长、比例和文件大小；不得把预览图当成原视频下载完成。
- 移动端使用吸底筛选入口，桌面端使用侧栏或顶部筛选。

### 3.2 详情页

- 图片原图预览；视频支持播放、拖动和查看基本信息。
- 显示标题、作者、来源、原始链接、标签、授权／使用边界和收录时间。
- 操作包括收藏、打开来源、下载（条件允许时）和“导入本地工作台”。
- 来源不清或授权未知时明确标注，不擅自声明可商用或可再分发。
- 不绕过原平台登录、反爬、地域或版权限制。

### 3.3 数据来源

优先复用现有参考、收藏和作品数据。确实需要新增时，使用统一 reference ID 和来源记录，避免同一素材在 gallery、favorites 和 reference 中形成无法对应的副本。

## 4. 第一期：导入本地工作台

### 4.1 用户流程

```text
搜索／收藏参考
  → 打开详情
  → 点击“导入本地工作台”
  → 官网创建一次性 ticket
  → 唤起 Refmuse 本地工作台
  → 本地显示参考预览与目标项目选择
  → 用户确认
  → 本地下载、校验、去重并创建参考节点
  → 官网显示已发起／已完成状态
```

未安装本地端时展示下载页；已安装但唤起失败时提供重试和手动下载／导入，不反复自动唤起。

### 4.2 深链与 ticket

首选协议：

```text
refmuse://import?ticket=<短期单次凭证>
```

ticket 只绑定 reference ID、版本、签发对象、过期时间和随机 nonce，不包含本地项目、文件路径或本地实例令牌。官网不得要求用户把本地令牌粘贴到网页。

建议接口：

```text
GET  /api/references?q=&type=&tag=&source=&cursor=
GET  /api/references/:id
POST /api/references/:id/import-ticket
POST /api/local-import/resolve
POST /api/local-import/complete
```

`resolve` 返回签名参考清单及短时下载地址；`complete` 只接收最低限度的成功／失败状态。详细错误和本地路径不上报。

参考清单至少包含：

```text
schemaVersion、referenceId、version、title、sourceUrl、creator、
license／usage、media[type, url, bytes, sha256]、preview、expiresAt、signature
```

### 4.3 状态与异常

网页状态统一为：待连接、等待本地确认、下载中、已完成、已取消、失败可重试。

必须覆盖：本地端未安装、版本过旧、ticket 过期／重放、下载地址失效、用户取消、磁盘不足、哈希不符和本地保存失败。网页显示“已发起”不等于本地已经成功，最终状态以本地确认结果为准。

### 4.4 安全边界

- 官网不能枚举本地项目、读取本地文件或获得本地 API 令牌。
- 下载必须使用 HTTPS，并限制 MIME、大小、重定向和最终 IP，防止 SSRF。
- 本地端只接受官方签名清单；ticket 短期、单次、可撤销。
- 本地项目导入必须经过用户确认，重复 ticket 不得重复创建节点。
- 不在 URL、日志、分析事件或错误报告中记录令牌、私人文件名和本地路径。
- 本地服务继续只监听回环地址，不因官网集成开放外部访问。

## 5. 第二期：`/local` 本地版下载页

### 5.1 页面内容

1. Hero：Refmuse 本地版、系统选择、下载按钮、版本、日期、大小和 SHA256。
2. 本地版特点：数据在本机、ComfyUI、无限画布、无云端积分消耗。
3. 线上与本地对比：算力、模型、项目存储、账号、安装和适用人群。
4. 系统要求：Windows、显卡／显存、磁盘、ComfyUI 和支持矩阵。
5. 三步安装：准备 ComfyUI → 下载安装 → 模型配置与校验。
6. 自有截图／演示：启动器、参考导入、画布、镜头／Take 和开源内容安装。
7. 模型说明：核心与完整配置、来源、许可、校验，不随下载包捆绑模型。
8. FAQ、已知限制、版本记录、隐私和反馈。

macOS 仅按真实支持矩阵显示，不在未验收前提供虚假的稳定下载承诺。

### 5.2 下载 API 与发布后台

```text
GET  /api/local/releases?channel=stable&os=windows&arch=x64
GET  /api/local/releases/latest?channel=stable&os=windows&arch=x64
POST /api/local/download-event
```

发布记录包含版本、渠道、OS／arch、文件地址、SHA256、大小、最低系统、说明、兼容性和发布时间。文件使用 R2／S3 或国内镜像，支持 Range／断点续传；下载地址可短期签名，不使用第三方短链。

管理后台支持上传、发布、下架、历史版本和回滚。发布包不得包含密钥、日志、项目、私人素材或模型权重。

## 6. 第三期：`/open` 开源内容中心

### 6.1 内容类型

| 类型 | 第一期策略 |
|---|---|
| Refmuse／H3 模板 | 优先，安装到本地 library，新建项目可选 |
| 提示词／风格包 | 优先，线上和本地按格式区分 |
| 完整示例项目 | 后续，必须排除私人素材并单独校验授权 |
| ComfyUI 节点包 | 后置，源码审核、权限提示、签名和重启确认 |

### 6.2 页面能力

- 首页：精选、最新、分类和专题。
- 搜索：类型、License、OS、ComfyUI 版本、更新时间和模型依赖筛选。
- 详情：预览、作者、来源、许可、兼容性、依赖、版本、更新记录和安装。
- 创作者：GitHub 信息、内容列表、更新和认证状态。
- 内容库：已加入、已安装、更新可用、打开本地和卸载。
- 提交与审核：GitHub repo＋固定 tag／commit、manifest 校验、人工审核、签名、发布、举报和下架。

v1 全部免费开源；“加入内容库”是免费授权记录，不建立订单或支付表。

### 6.3 本地安装

“安装到本地”与参考导入复用连接层，但使用独立的 `.h3pack` 清单和安装事务。必须校验 SHA256、签名、License、兼容性和压缩包路径；失败回滚，不修改已有用户项目。

## 7. 数据模型建议

优先复用 users、favorites、gallery 和现有管理后台。确需新增时建议：

```text
reference_items        参考元数据、来源、作者、类型、授权、状态
reference_assets       预览与媒体地址、大小、哈希、时长、尺寸
reference_imports      ticket nonce、参考、过期、状态和最低限度结果

local_releases         本地下载版本、文件、哈希、兼容性与发布状态

open_items             开源内容条目
open_versions          固定 tag／commit、manifest、签名包和哈希
open_creators          创作者与 GitHub 信息
open_library           用户已加入内容
open_installs          可选安装状态同步
open_reports           举报、审核与下架
```

所有表使用稳定 ID、创建／更新时间和状态字段。列表查询建立必要索引；不在日志和分析表中保存明文 IP、令牌或私人内容。

## 8. 账号、设备与隐私

第一期参考导入不强制接入完整设备账号体系。后续需要跨设备内容库时，再增加设备码登录和系统凭据存储。

默认不上传本地项目、素材、生成结果和文件路径。安装状态、版本、OS／arch 和统计数据分别提供隐私说明及开关。作品发布到作品广场必须由用户主动执行。

## 9. 视觉与品牌

官网统一使用 Refmuse 名称和新图标。图标采用“R＋播放＋画布节点”的简洁几何方向，输出 SVG、favicon、多尺寸 PNG 和社交分享图。

复用现有 secondary header、主题变量、按钮和卡片体系，新增参考、本地版与开源内容样式文件。不得复制参考网站的商标、图片或未经授权的设计资产。

## 10. 非功能要求

- 中文完整，英文作为后续增强。
- 页面支持键盘、焦点、对比度和 aria；移动端可完成搜索和导入发起。
- 参考与下载页提供服务端渲染或静态 HTML、title／description／OG 和 sitemap。
- LCP 目标小于 2.5 秒；缩略图使用 WebP／合适尺寸，详情媒体按需加载。
- 列表使用游标或分页，避免一次加载全部参考和开源内容。
- 管理操作有权限校验、审计记录和回滚。

## 11. 实施阶段

| 阶段 | 周期 | 交付 | 完成标准 |
|---|---:|---|---|
| M0 基线与品牌 | 1 周 | 域名、部署 tag、线框、路由映射、接口 schema | 基线可回滚，评审通过 |
| M1 参考搜索 | 1–2 周 | 搜索、筛选、详情、来源、收藏 | 图片／视频可发现并追溯来源 |
| M2 本地导入 | 2 周 | ticket、深链、状态、异常与手动回退 | 官网到本地画布闭环通过 |
| M3 下载页 | 2–3 周 | `/local`、API、后台、镜像和文档 | 干净 Windows 按文档安装成功 |
| M4 开源内容 MVP | 4–5 周 | `/open`、提交审核、内容库、种子内容 | 浏览→加入→安装闭环通过 |
| M5 本地包与账号扩展 | 2–3 周 | 安装／更新／卸载、设备授权、可选同步 | 回滚、撤销授权和隐私验收通过 |
| M6 发布加固 | 2 周 | 安全、SEO、监控、客服、回滚和文档 | 上线清单全部通过 |

参考搜索与本地导入 MVP 目标为 4–6 周；完整官网能力按约 10–13 周规划。阶段可并行，但不得用未验收的 Mac、安装或本地导入状态作为已完成宣传。

## 12. 验收矩阵

### 功能

- 搜索、筛选、详情、收藏和来源跳转正常。
- 图片与公开视频参考都能发起本地导入。
- 未安装、旧版本、取消、失败和重试均有明确路径。
- 网页状态与本地真实结果一致，不把已发起冒称已完成。
- 本地下载、安装文档、开源模板安装和更新形成闭环。

### 安全与隐私

- ticket 重放、过期、伪造签名、错误哈希和非法下载地址被拒绝。
- 官网无法读取本地项目、文件、路径和实例令牌。
- 管理接口越权、CSRF、XSS、Markdown 注入和压缩包路径穿越有测试。
- 开源内容无 License、携带密钥／模型权重／私人素材时不能上架。
- 日志、分析和错误报告不记录敏感信息。

### 兼容与回归

- 现有登录、收藏、作品广场、线上画布、积分和管理后台不回归。
-  Windows 主流浏览器验证深链和手动回退；Mac 按实际支持矩阵执行。
- 移动端、键盘、慢网、大文件和下载中断场景通过。
- 测试使用合成素材和临时项目，不读取真实私人内容。

## 13. 指标与上线

核心指标：搜索成功率、详情打开率、导入发起率、本地导入成功率、失败原因、下载成功率、开源内容安装成功率和举报／下架情况。

上线前完成：正式域名与 HTTPS、部署基线、数据库迁移与回滚、错误监控、隐私与内容政策、安全私报、种子内容、SEO、下载镜像和客服说明。

上线顺序：内部预览 → 小范围参考导入 → 本地下载页 → 开源内容中心 → 全量开放。任何阶段均可独立关闭本地导入或内容安装，不影响既有官网和本地创作。
