# MeshAnything V2：原生能力、本机使用与开发方向

日期：2026-11-03。对应 PRD 修订 1.1.5；目标功能仍为画布 1.1.0。范围：官方源码/论文、本机适配和历史回执审计，以及独立离线 token 结构实验。没有启动新推理、修改权重/运行时或生成新模型。

## 1. 结论

现有权重原生支持“给定形状的三角低模候选生成”，不支持源 UV/材质保留或输出。原因在实际数据路径：输入为8192个位置＋法线点，输出为三角形坐标，没有源 UV、纹理、颜色或材质条件，也没有相应输出头。不是尚未打开某个开关。

模型仍有可研究空间，但主要在输入选择、候选策略、解码约束、验证及后处理。不能把基础库接口存在或内部参数可修改当成现有权重已掌握新任务。AI 新低模＋外部 UV/材质对烘仍是可行主线，不需要为对烘本身重新训练 MeshAnything。

## 3. 能力边界

| 问题 | 当前事实 | 对产品的含义 |
|---|---|---|
| 已有 UV/材质能直接保留吗 | 输入只有 XYZ＋几何法线；模型输出只有坐标；官方 OBJ 的橙色是固定展示色 | 原高模 UV/材质必须另存；AI 后新 UV 对烘，不是模型恢复颜色 |
| 可以直接指定500/800面吗 | 推理无目标面数条件，参数只有输入与 sampling；内部1600用于序列预算 | 继续使用后处理LOD，不把设置token长度当精确面数控制 |
| 最多1600面吗 | 论文/README的训练与宣称范围是1600；代码没有按第1600面硬截断 | 本地1766/1956面不是解锁了更高保真能力；显示实测值与训练范围，不作硬上限保证 |
| 提高分辨率就能更精确吗 | MC分辨率影响输入；输出坐标仍按128档量化 | 改MC不等于提升输出坐标精度；直接改量化档数会影响词表/权重，不能当普通设置 |
| 是否保留原顶点、部件或指定局部 | 公开入口没有原网格前缀、锁定面或语义部件条件 | 外部分件/对应/拼缝要自研；任意部分网格续写仅是待研究方向 |
| 能否直接出四边面/动画布线 | 当前解码为三角面，未提供骨骼/变形约束 | 不宣称可直接得到角色变形拓扑 |
| 是否包含UV/材质训练 | 当前可见训练表示与损失围绕几何token生成 | 原生UV/材质控制需新增表示/条件/训练数据和训练验证，不是调提示词或加普通LoRA即可保证 |

输出量化步长在模型输出坐标中为1/128；对应到原模型需应用已记录的逆变换。它是表示分辨率，不是几何误差上界。细小结构可能被合并；增大token预算不能解决坐标量化问题。

MC使用绝对SDF偏移等值面，会改变表面、厚度、法线分布和采样，不能当无损封口。官方论文第5节明确指出精度仍不足以满足工业应用，需要改善稳定性和准确性；不能只靠“模型成功输出”省略几何和烘焙质量门。

## 4. 本机已经用到哪些设置

已完成MC256、8192点、官方CLI预处理、贪心seed0及随机seed0/1/2；随机用官方 `top_k=50 / top_p=0.95`。未发现漏加载部分权重的证据，已有严格key/shape/hash加载回执。

以下来自历史记录，本轮没有重新生成：

| 候选 | 清理后三角面 | 面连通分量 | 报告相交对 | 原扫描→结果采样P95偏差（包围盒对角线百分比） | 推理秒数 |
|---|---:|---:|---:|---:|---:|
| MC256 greedy seed0 | 1766 | 1 | 2 | 1.371% | 146.11 |
| MC256 sample seed0 | 1956 | 33 | 967 | 1.017% | 182.73 |
| MC256 sample seed1 | 1951 | 7 | 113 | 1.072% | 187.13 |
| MC256 sample seed2 | 1657 | 1 | 44 | 1.055% | 153.56 |

距离指标基于4096独立表面样本，不能代表连续表面误差上界；更低距离没有带来更干净拓扑。随机种子同时改变输入点采样和解码随机性：greedy0/sample0的输入哈希相同，sample1/2不同。因此现有多seed试验不是“固定点云、只改解码”的完整消融。

四例都以EOS结束，没有用尽10083个新token预算；sample1却在解码中遇到只有6个坐标token的新条带分隔符，尚未构成首个三角形，官方解码器提前停止，后续230个返回token未进入网格。这个事实不代表可以删除分隔符后继续拼面。

Windows SDPA替换了官方硬编码FA2/BetterTransformer，CPU对照已做；官方GPU FA2与本机CUDA FP16的同输入输出差异尚未完成对照。不能把未测差异说成已排除，也不能先认定它就是质量不足的原因。

## 5. 值得开发的方向与优先级

| 优先级 | 方向 | 是否需要新训练 | 验收重点 |
|---|---|---|---|
| P0 | 输入采样seed与解码seed分离，冻结输入后比较有限候选 | 不需要；需改调用包装 | 输入hash相同、解码参数可重放；相同预算下看拓扑/轮廓/可烘焙性，而非只比距离 |
| P0 | 语法约束解码：屏蔽不完整条带的分隔符/结束符及非法特殊token | 可先用现有权重研究 | 约束必须在采样前改变允许token，不能事后伪造修复；对照有效终止、几何质量、耗时和失败率 |
| P0 | 候选质量筛选与受约束贴合，接原高模材质对烘 | 不需训练MeshAnything | 保留原候选，避免选出距离好但自交/碎片多的结果；检查最终UV、Cage与材质 |
| P1 | 比较原表面点云与MC预处理，按模型特征推荐 | 不需要 | 固定比较条件，记录厚度/边界变化；薄片、开放岩壁不能机械套MC |
| P1 | 真正官方FA2 GPU与本机SDPA的受控对照 | 不需要新权重，但需要合适环境 | 同权重/输入/精度/解码配置，区分数值差异与质量因果，不改现有稳定环境来试 |
| P1 | 独立部件分别生成、大资产分件后组装 | 可先不训练，能力待实验 | 优先已独立部件；记录各自归一化/逆变换；相邻连续表面需要边界约束与拼缝，不按网格切块后直接焊接 |
| P2 | 批量资产/候选任务产品化 | 不需要 | 先串行队列和模型复用，再测batch显存/隔离；已有batch入口不代表本机已验收 |
| 研究项 | 前缀续写/局部保留 | 尚无可靠公开接口，是否需微调待实验 | 自回归表示不自动提供网格编辑语义；状态机、保留范围和质量需验证 |
| 另立研发范围 | 模型原生UV、材质、面数条件、可靠语义部件控制或更高坐标精度 | 涉及新表示/条件与训练或微调验证 | 训练数据与许可证、资源、任务定义先明确；不纳入首版隐性承诺 |

当前不建议优先用更多随机seed、MC512或更长token预算盲目压榨模型。先完成P0的可解释对照，才决定是否值得扩大推理成本。官方提供训练代码，但不能据此推定本机小规模微调能得到可靠新能力。

## 6. 离线语法实验的范围

在画布仓库忽略缓存 `.cache/meshanything-capabilities/probe/` 已制作独立结构预检原型；不接生产推理、不修改原token、不写新网格。使用合成边界用例和历史四例token进行只读检查，对照原解码诊断。详细结果在该目录的 `report.json`，仅本机研究缓存，不纳入发行包。

主审已阅读实现并独立重跑：21项测试通过，4例历史诊断的位置、原因、坐标计数和分隔符计数全部匹配。greedy0/sample0/sample2语法有效；sample1原始序列零基位置8989（调整后8988）出现token131，此条带只有6个坐标。该选择可由约束器提前禁止；禁止后产生什么网格尚未测试。报告保存输入token/诊断和脚本哈希，源token读取前后哈希一致。

复现命令（`<RUNS>` 为本机历史实验 `artifacts/meshanything_official_settings_v1/runs` 的绝对路径，`<HEAD>` 为记录的仓库提交）：

```text
python -B .cache/meshanything-capabilities/probe/probe.py --source-root "<RUNS>" --baseline "<HEAD>"
```

API在原始返回token上检查初始BOS、完整非空条带EOS及EOS后PAD；单独记录官方先补齐再 `[1:-1]` 的行为，区分真实EOS和填充EOS。这个检查器刻意比官方特殊token终止策略严格，不是假装逐字复现完整解码器。纯语法三角数也不等于去除退化/重复面后的真实面数。

目的仅是确认非法token选择能否在生成时被明确识别。语法合法不保证无退化/重复/自交，不保证几何更准；即使某一步被屏蔽，下一步会生成什么也需要真实推理才知道。未获得新的模型对照前，不把结构预检通过称为模型质量提升。
