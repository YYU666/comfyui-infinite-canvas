# 画布长视频四角色替换：调研与开发方案

> 后续修订（2026-11-10）：已补充 [基础视频编辑与长片处理方案](VIDEO_EDITOR_MVP_RESEARCH_2026_11_10.md)，核查用户新提供教程的公开 TimelineDirector、h3-motion-transfer 工作流和 Skill。当前多人短片未通过衣服/运动验收；此前“必须拆四次再合成”不再作为唯一主线，优先验证 Viggle Remake 同场关键帧方案。各引擎的参考、前缀帧数和采样配方保持独立，基础剪辑先形成不依赖 Agent/ComfyUI 的闭环。本文较早的候选参数和研究限制属于历史记录，以后续修订为准。

日期：2026-11-10。状态：调研与设计完成；尚未实现或提交整片换人生成。

## 1. 本次目标与边界

用户把原片中的四名唱跳主角替换为已准备的四个角色，保留原表演、运镜、剪辑、伴舞、舞台和原音轨。一个画布任务覆盖全片，支持暂停、重启恢复、局部重试，默认只在当前节点显示最终视频。

当前素材经既有下载验收：195.84 秒，1024×576，约 29.97 fps，AAC 立体声。不是恰好 180 秒；制作范围必须按实际视频时间戳确定。四张角色参考已在新视频项目；四个角色对应原片哪四位演员尚未指定，不能按画面从左到右永远编号，也不能替用户随意确定选角。

本轮 CEO-only：核验本地源码及公开上游文档，形成设计，不修改运行中的服务，不下载权重，不启动 GPU 生成，不发布 GitHub。

## 2. 已确认的实际能力

| 层级 | 核验结果 | 含义 |
| --- | --- | --- |
| 画布 `src/workbench-api.js:durationToFrames` | 上限 362 帧 | 当前入口依然限制短片 |
| `buildCharacterSwapWorkflow` | 分窗前从第 0 帧截取；只接受一个 identity；SAM3 跟踪 max_objects=1 | 不能将当前节点直接当作全片四人功能 |
| 帧率 | 当前 GetVideoComponents 后按源帧数取帧，再按 24 fps 输出 | 29.97 fps 素材必须按时间重采样，不能直接更改输出 fps |
| 本地 ComfyUI `nodes_minimax_h3.py` | Ref2VA 最多 9 个图像参考；length 控件可高于 362，但注释训练范围约 124–362 | 多参考输入有基础；长输入框不等于长片稳定支持，更不等于四身份空间绑定 |
| H3 Relay Windowed Edit | 原视频条件＋固定人物参考＋生成历史，精确帧组装，持久检查点、前缀复用、reroll | 现成可复用的长视频分窗基础 |
| H3 Relay 人物接口 | 文档明确只使用参考 batch 的第一张，single-character contract | 直接塞四张图不会自动获得四人替换 |
| H3 Relay 准备节点 | 当前 README 已包含 LabsH3PrepareVideo，duration=0 保留整片，24 fps 规范化 | 旧说明中“必须独立 labs-video-prep 包”已过时；接入前查在线注册，避免重复安装 |
| 内存 | Windowed Edit 文档明确不是流式实现，帧/检查点随时长增长 | 不能只取消 15 秒上限就交付整片功能 |

源码与外部工具的能力应分开记录：支持九张参考，不证明能够对四个人分别施加身份约束；支持循环生成，不证明接缝质量已通过验收。

## 3. 公开方案比较

此次直接读取项目官方 GitHub README/指南，均获取成功；不是全网穷尽调查。下载文本及状态记录在本机 D 盘研究目录，未纳入公开源码。

1. **H3 Relay**：最接近已有环境，提供窗口历史、输出检查点和恢复。默认目标窗口 124 帧、历史 18 帧，24 fps。其测试保证帧组装/缓存规则，作者明确说不保证人物一致性和接缝质量。作为主线复用，不能宣称已有完整四人方案。
2. **SAM 3 / SAM 2**：视频实例分割与跟踪工具，提供人物遮罩。SAM 3 官方还列出 3.1 Object Multiplex 多对象共享内存方案。当前画布已调用 SAM3，优先复用，不自动更新模型。跟踪不等于跨镜头人物身份识别，需要独立的原演员身份关联与纠错。
3. **ByteTrack**：可参考其遮挡下的多目标轨迹关联方法。不能只靠矩形框或运动预测解决跨镜头重识别、相似服装、转身和长遮挡。
4. **Wan2.2-Animate**：官方提供 animation/replacement，使用姿态、脸部视频、背景、mask，替换可用 relighting LoRA。**官方预处理指南明确警告：内置 mask 提取仅适用于单人，多人需要另开发或接开源工具。** 可作为单人轨道的备选引擎，不是四人长视频现成替代。不能把 Wan2.2 其他模型的显存数据当作 Animate 的本机实测。
5. **VACE**：有 reference-to-video、video-to-video、masked video-to-video，可组合视频、mask、多参考。适合评估受控编辑备选，不证明四人绑定更优或无限时长。
6. **PySceneDetect**：镜头切分候选。舞台闪光会产生假切点，需要比较相邻帧结构、最短镜头时长及可调整切点。
7. **ProPainter**：适合研究衣服轮廓变化后暴露背景的时间一致修补，不是身份替换模型；公开许可为非商业，不能直接作为本产品默认商用依赖。

## 4. 推荐处理链

### 4.1 建立原片时间轴

- 读取视频/音频实际时间基、起始 PTS、帧率、色彩和旋转信息；保存原音轨。
- 生成低码率代理供浏览器预览；原片与生成中间件按窗口从磁盘解码。
- 检测切镜头，保留源时间映射。先采用模型原生 24 fps 时间轴，依时间戳重采样，不改变表演速度。
- 生成总帧表，按全局时间轴取整一次，再分配镜头范围；禁止每个小段分别四舍五入造成累计漂移。保留起始音画 offset。
- 导出可先提供 24 fps。若要求原片帧率，再统一重采样；插帧是可选后处理，不保证手指/嘴型无伪影。

### 4.2 四人绑定与遮挡

- 在可辨认的原片帧上选中四人，创建永久 actorA/B/C/D，各绑定一个 characterAssetId。位置、框编号仅是轨迹观测值，不是身份。
- 每个镜头维护 shotTrackId → actorId；在原视频上用脸、服装、姿态、运动连续性做关联。不可用已生成的人脸反向判断原演员是谁。
- 新镜头先自动关联，置信不足显示候选原演员缩略图供确认；没有可靠证据就不得悄悄换人。四人离场时不凭空补齐四人。
- mask 覆盖身体、头发、服装、运动模糊边缘；可纠正漏分/误分。保留伴舞、麦克风、前景手臂等遮挡关系。
- 现有固定 expansion_px=64 对四人挤在一起有污染风险。改为跟人物尺度关联的范围，并扣除受保护人物/前景，不能让四个人的编辑区域无条件重叠。
- 替换角色衣服更宽/更窄时，源人物 silhouette 不足以作为最终 alpha。须评估生成后轮廓、背景补洞和时序 matting；这是分层方案的核心难点。

### 4.3 生成策略：先对照验证再固定默认

**方案 A：多人联合生成（候选）**

一窗同时提供四个按固定顺序登记的角色参考、源视频、该镜头的演员对应说明与联合编辑区。优点是人物接触、遮挡、灯光有整体上下文，计算次数较少。缺点是目前接口没有经验证的“每个身份参考绑定独立 mask”硬约束，提示词绑定可能串脸/串衣服。不能因为能输入四张图就宣布可用于整片。

**方案 B：按人物受控生成＋合成（对照基线）**

每次针对一个 actor 的 mask 和参考生成，保留其他人物/场景条件；最终只合成经检查的修改区。生成结果不能简单四次覆盖全画面，否则会累积背景和他人变化。应保留不可变原视频、独立人物候选层、遮挡/alpha 数据、版本化合成结果。角色轮廓变化、头发透明边、相互拥抱/交叉手臂处需要专门处理，可能仍需联合修补片段。

先比较 A/B 在同一批短镜头的身份准确性、遮挡、细节、速度，再确定默认或镜头级混合策略。稳定性优先，但不能未经测试称分层法必然最好。四人各跑一遍也不是无需工程工作的万能方案。

角色参考每窗回到固定角色素材，前窗生成帧只提供连续性，避免上一窗的偏差逐步变成新身份。首版不训练角色 LoRA，除非短片证明身份条件本身不足。固定 seed 用于复现，不是身份锁。

### 4.4 同镜头分窗与接缝

- 初始候选沿用 124 帧目标＋18 帧历史；这是现有上游默认，不是已验证最优。简单镜头可测试更长窗口，复杂多人交叉可缩短。
- 历史 18 表示 17 个过去帧＋1 个边界，不是每窗直接扣 18 帧。按 Relay plan 的 source 范围、target 大小、padding 和边界计数组装。
- 同镜头每窗使用源视频＋固定角色身份＋已接受历史，校验接缝的脸、姿态、衣纹、光照与运动。
- 硬切处结束延续历史，重建镜头内轨迹，但保持全局四人角色绑定；不强行把上一机位的构图带进下一机位。
- 不默认 crossfade 人脸。发现接缝跳变，选择同镜头低运动边界或重算跨接缝的小段，必要时重新生成受其历史影响的后续窗口。
- 不用光流数值作为绝对拦截标准：舞台灯光、遮挡与真实切镜头可造成大变化。异常标记到时间轴，允许人工接受质量警告。

### 4.5 整片后台任务

前端一次提交 ProjectVideoJob，后端持久调度镜头/窗口/人物任务。刷新、切项目、关闭页面后可以继续运行；最终项目写入仍经当前画布单写通道，后台不得覆盖 project.json。

每项存储：原片 hash、PTS/帧区间、角色映射版本、mask 版本、模型与 LoRA 指纹、prompt 版本、seed、采样参数、历史依赖 hash、实际帧数、耗时、产物地址与状态。幂等键避免重连重复提交。

状态：待分析 → 待绑定确认 → 预处理 → 生成第 X/Y 窗 → 合成/音轨 → 已完成/有警告；另有暂停、失败可重试、等待身份确认。提供已完成可播放片段、总进度、当前步骤耗时、预计剩余时间。

重试只处理选中人物/镜头/窗口及依赖项。更改历史会影响同镜头后缀，UI 明确提示实际范围；不会重跑没有依赖的其他镜头。若下游合成使用已修改人物作为条件，必须登记该依赖，不能误报仅重算一层。

生成失败有有限自动重试及可调整参数，不无限循环。技术失败（文件损坏、缺帧）阻止最终交付；质量警告允许预览及人工接受。不能将漏处理片段静默作为原片导出并声称换人完成。

## 5. 内存、时长与恢复

- 195.84 秒约 4700 个 24 fps 帧；按 124 帧且延续时重用 1 边界，不考虑切镜头约 39 窗，粗略称 40 窗。实际按镜头规划后重新统计，不能预先写死。
- 若每窗四人分别跑，计算调用量可接近四倍；人物不在场则跳过。推理用时必须用本机多人片段实测，再按各镜头可见人物数、窗口大小、分辨率估算。不要把单人 5 秒耗时等同四人耗时。
- 时间估算 = 预处理 + 所有实际生成窗口耗时 + 重试 + 合成编码；同时显示加载、跟踪、采样、编码的分项计时，避免只显示“生成中”。
- 约 4700 帧 1024×576 RGB float32，仅一个全片像素张量就约 31 GiB，不含 masks、模型和多副本；8-bit RGB 也约 7.7 GiB。逐窗 GPU 不能自动解决全片 CPU 内存问题。
- 后端窗口解码、有限缓存、检查点落盘。缓存盘用户可配置，当前机器优先使用 D 盘；作业前估算空间。保留恢复所需精度，不能以有损 MP4 当作等价历史检查点。
- GPU 队列与生图任务共享调度，默认串行重计算，暂停在安全窗口边界；不杀其他线程任务或偷偷释放正在用的模型。
- 独立镜头可以调度并行，但单 GPU 默认不并行。重启后查 Comfy job 状态并对账再恢复，防止重复生成。

## 6. 画布产品形态

一个「长视频角色替换」节点：原视频入口＋角色 A/B/C/D 入口；节点内显示总时长、进度、结果播放器。高级设置折叠，不铺几十个重复结果卡片。

双击进入时间轴编辑面板：

- 原片/结果同步预览，四个角色轨道和遮罩叠加；可以逐帧与缩放。
- 镜头切点、原演员↔角色映射、漏追踪/串脸疑似位置。
- 操作：绑定角色、试做选区、生成全片、暂停/继续、重做选区、调整遮罩、接受质量警告、导出。
- 参数：全片/选区、分辨率、窗口与历史长度、保留音轨、随机种子、局部 mask 扩张/羽化、联合/分人策略。参数改动提示受影响范围。
- 首版提供切分、选区、段落重试、音轨保留与导出；不同时开发通用多轨 NLE、转场素材库或复杂特效。

## 7. 分阶段验收与停止条件

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M1 时间轴与绑定 | 原片分析、镜头列表、四轨绑定、低清 mask 预览 | 交叉换位仍跟对人；硬切重识别可纠错；不启动整片生成 |
| M2 代表片段 | 独舞近景、四人同框、交叉遮挡、切镜头，比较联合/分人方案 | 不明显串脸串衣；动作和伴舞保持；用户可接受身份表现 |
| M3 全片调度 | 后台队列、窗口缓存、进度、暂停与重启恢复 | 页面关闭/重启恢复无重复；失败重试范围准确；有完整计时 |
| M4 整片导出 | 连续片段组装、原音轨、局部修正 | 覆盖全时间轴，无重复/漏段；全片音画偏差不累积，目标≤1个输出帧；全片复查四身份与接缝 |

M2 若四人绑定不稳定，保留对照证据，调整跟踪/合成或更换单人生成引擎；不靠盲目增加整片重试次数。无需每个轻微美术问题都阻止后续预览，但不能将串脸和漏替换默认为合格。

## 9. 后续确认：人物先测，场景后置

用户已确认暂不替换场景，先做人物短片测试。背景替换待人物流程检验后另行设计，可能需要多个机位的场景参考。

2026-11-10 用户接受首测对应：黑短发白长袖→白发紫衣；棕长发齐刘海黑长袖→浅蓝；侧分长发无袖→白蓝裙；卷长发黑短袖白腰身→红裙。对应按原演员保持，不随左右换位改变。

现有四视图是正面/45°胸上头像加无头身体参考，缺少后脑、盘发/马尾连接及饰品背面。建议独立补充原角色“头顶到发尾”的完整背面参考；复杂发型再补侧后45°，不改变已确认四视图版式。仅通过模型生成未见角度属于设计推测，需确认后才能作为固定发型依据。首测可继续，背面发型暂不验收为最终方案。


## 2026-11-10 实测：遮罩数量与性能诊断

- 已生成尾段41帧（1.708秒），不是完整15秒；审图只换了白蓝角色，其余主演仍为原演员。
- 已保存遮罩证据，根因之一明确：SAM3 普通 `person` 条件默认 `max_detections=1`。`individual_masks=false` 只合并已保留检测，并不解除人数上限。`sam3_clip.py` 支持 `类别:N`，多类别以逗号分隔。
