# UV耗时、重复计算与可靠性修复

文档修订1.1.29，2026-11-05；目标功能仍为1.1.0，未发布。本轮用户确认1.1.28流程，同时要求解决耗时长、反复失败和整轮重生成的问题。

## 实际诊断

用户等待由算法计算、质量检查、导出/保存、Agent返工叠加而成。此前只记录总时长，不能精确把历史218秒分摊给每个阶段，也没有与同机原始工具的同质量基准；不能宣称画布已经更快。

- 最近正式UV任务总用时218.38秒。它消费已经保存的高模AI/AO计划，未重新推理AI，主要执行CPU展开、排布、检查与导出，不能归因于GPU不足。
- 上一任务因末尾报告序列化失败，同样花了约218秒，后来全部重算。之前没有“UV阶段已验证、仅尾段失败”的可恢复入口。
- 轮廓排布候选已做过完整几何检查；若该候选被选为最终UV，最终步骤又检查相同坐标。对保存的100000面、4096分辨率、16像素间距结果做一次独立测量：完整检查48.8535秒，精确匹配复用0.000681秒，全部指标一致。这只是单项检查证据，不是整流程提速倍数。
- 反复更换切缝/展开路线、硬阈值误拦、临时诊断展示与需求偏离造成大量返工。缓存与加速不能自动解决这一质量问题。

## 已实施

### 1. 同一份排布不做两次相同几何检查

同一次展开内，比较模型顶点、三角索引、UV全部数组的类型、形状、精确值以及分辨率和间距。只有全部一致才复用。候选没被选中、单个坐标变化或检查条件变化都重新检查。像素检查仍独立执行，原质量条件不削弱。

### 2. 已验证UV阶段可恢复

源高低模型、切缝计划及参数、实际几何、相关程序源码和依赖版本共同形成缓存身份。只有全部必要检查已完成且计划缝线与来源映射核验通过的阶段才能保存。缓存包含精确几何/UV/来源映射、完整报告和派生图，原子提交并校验大小和内容哈希，不读取pickle。

下一次同条件任务仍先校验计划/输入，再恢复UV，重新核验来源映射与已确认切缝，正常执行导出、预览、报告及任务清单验收。材质、法线和属性从当前源模型按映射恢复，不信任缓存的任意模型metadata。

缓存不把任务变成成功、不把needs_review变成合格，不修改历史failed任务。旧packed-uv-unchecked等诊断不能自动晋升为有效缓存。新机制只对加入后新算出的合格阶段有效；本轮没有为启用缓存重新生成用户模型。

损坏或旧版本缓存当作未命中。不能缓存的旧试展开仍沿原路径交付，不新增质量硬门；缓存不可写不会丢弃已算成果。修改参数/实现版本采取保守失效，不冒险重用。

### 3. 报告预检和真实阶段进度

UV报告的类型/有限数值在阶段边界检查，导出前检查现有4MiB传输预算。非UV任务不新增限制。页面可收到展开、重叠检查、方向/排布、候选检查、像素间距、最终核对或复用已验证阶段的进度；阶段百分比仅表示流程位置，不是剩余时间预测。

报告新增各阶段实际耗时、相同检查复用次数、缓存状态。缓存命中时原计算耗时与本次恢复耗时分别说明，不把原来的计算时长冒充本次时长。

## 修改范围与重算边界

| 用户动作或故障 | 当前实现的行为 | 尚未实现的更细优化 |
|---|---|---|
| 同一UV任务导出/预览尾段失败后重新提交 | 条件完全一致且已有已验证阶段时，复用UV，只执行尾段 | 自动在原任务中重试某个导出步骤 |
| 当前页保存/交付失败 | 继续已有“重新交付”路径，不重新提交求解 | 通用全链恢复需继续验收 |
| 模型/计划/切缝变化 | 旧UV缓存失效，重新计算必要流程 | 每个局部岛独立缓存与局部重展开 |
| 分辨率、间距、排布或朝向变化 | 当前完整UV阶段键失效，保守重算 | 参数化、方向、排布分层缓存，避免全部展开 |
| 仅查看灰模/切缝/棋盘/图集 | 读取已完成结果，不计算新UV | 更多视角预览缓存 |
| 同一排布重复几何检查 | 本次调用内精确复用 | 不跨不同坐标推断检查结果 |

本轮还不是整个制作链的增量任务系统，不能把表格右列当成已实现。

## 验证与限制

31项联合测试通过，覆盖：输入/计划/参数/代码/依赖变化使缓存失效、损坏缓存、源映射、非有限坐标、旧诊断不被采纳、质量待审不自动升级、保留原检查条件、进度单调、相同几何检查复用。

真实小模型故障注入：第一次在UV成功后让预览导出抛错；第二次任务禁止调用UV求解器，仍正常生成结果清单及全部文件，旧失败目录仍没有成功清单。这验证尾段恢复链，不是10万面新UV的视觉验收。

另有20项实施阶段测试及一次现存10万面UV几何检查基准。证据位于本机 `.cache/native3d/uv-reliability-v1/`。不为了性能验证重复生成用户资产，不需要前端重建；新后台worker启动时读取新代码。

当前仍未证明正确结构切缝方案的整模一次成功率，也未证明全流程快于Blender/SP等原工具。最新圆盘UV仍是用户否定的实验，不因缓存修复而获认可。

## 后续质量闭环

后续不能靠自动多轮整模重试营造“一键”。先固定1.1.28流程与预设，定位具体不满足展开条件的块/凹槽，检查真实开口、连接关系、局部拉伸及重叠；先在这些局部验证修正，再做一次完整对照。若同原因再次失败，停止同参数整模重放，保留失败阶段和局部证据。

产品验收应同时记录总耗时、各阶段耗时、人工调整次数、首次可用率、重复提交成本与实际视觉质量。时间预算和代表性资产集仍待实测确定，不虚构“多少秒内必成功”。Agent的决策错误和返工时间也算用户成本，不能只统计模型运行时间。
