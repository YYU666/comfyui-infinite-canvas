## 手动局部修复按钮（1.1.42）

边界检查未通过的LOD卡片和诊断窗口新增「尝试局部修复」。点击后，画布创建并保存独立修复节点，再提交后台任务；输入绑定该失败任务的最终候选文件、网格哈希和原高模。保留原候选，不从父LOD重新减面，也不重跑整条链。重复点击复用同一尝试；保存失败不提交计算，交付失败优先重新交付。

首版采用有界传统算法：最多处理4个不同原始面的局部边界，最多增加4个三角面，仍受用户明确面数硬上限和父LOD面数约束。减面软目标不再阻止必要的小范围加面。单处位移仍不超过模型对角线的0.002，原有边界、相交、法线及形状检查保持；不支持所有类型的网格错误。修复成功才开放UV等下游入口；未通过保留原候选与定位证据，明确提供「返回原候选 / 保留更多面」，不会自动反复重试。

真实超限的合成样例修复通过。当前岩壁最新LOD4离线尝试约8.67秒，由于需要的局部位移超过保护范围而未通过；没有把它标为修复成功。旧自动修复的保护策略未改变。新版手动修复的详细报告和标记可检查，旧版自动修复对照图接口尚不覆盖新版手动流程。

## 问题确认后的处理引导（1.1.41）

“检查确认”只说明问题真实存在，不代表已经修复。失败LOD卡片与诊断窗口现在同时说明失败原因、可操作的下一步以及当前修复状态。

对于本档外轮廓偏差超限，可选择“创建调整草稿”：默认建议在原保留比例上增加20%，也可修改比例；以原LOD0为百分比基准，从已验收的直接父LOD重新减面当前档。当前LOD4示例为1.25%（1249面）调整至1.5%（约1499面）。草稿自动连接正确父模型和原高模，换新种子，只创建并保存，不启动计算。用户检查后点击生成；通过后再使用“制作UV”等后续入口。

这不是当前候选的局部修复，也不保证一次通过。几何质量阈值保持不变；目标必须低于父级面数且不突破已有硬上限，没有增加空间时说明原因并禁用。重复点击复用未修改草稿，已修改/运行的草稿不覆盖；保存失败可重试保存，不重复提交计算。

本例1249面候选的确认偏差为130.006 mm，允许81.389 mm，完整自交检查为0。有限局部修复试验仍未通过独立边界检查，未接入正式结果，也未提供误导性的“一键修好”。现有已支持的自动局部修复仍按原能力运行。本轮未重算其他LOD，未上传或发布。

## 手动下一步与独立修复对照（1.1.40）

这次补齐已完成结果节点的手动后续入口；不需要Agent创建连线。点击“下一步”只创建并连接处理节点，检查设置后由用户点击生成，不连跑整条流程。

1. 在通过检查的LOD结果上，点击“继续LOD1…LOD4”，从这一档作为直接父模型创建下一档。沿用原高模、原LOD0百分比基准、原比例和硬上限，使用新种子；不继承上一档临时比例覆盖，不重新跑之前的LOD。已到LOD4就不显示继续LOD。
2. 点击“制作UV”，创建切缝方案并连接当前LOD和原高模，准备4096分辨率、16像素间距。先查看模型朝向并按实际情况确认，再点击“预览切缝”。方向确认不会替用户默认勾选。
3. 切缝结果双击进入3D审阅；确认当前方案后，“展开UV”才可用。该入口连接原低模、原高模和已确认切缝方案；原设置或来源改变时需重新检查。
4. UV完成后检查图集和表面棋盘，点击“烘焙材质”创建4096×4096烘焙节点。低模自动连接；带材质原高模需用户接入，界面明确提示，不根据文件名或相似几何猜测。此步骤尚不自动运行烘焙。
5. 失败结果保留诊断/重试入口，不出现可绕过几何检查的下一步。成功结果把下一步放在前面，重新生成与调整收进次要入口。

旧版通用结果若不是报告里已登记的具体LOD文件，会提示先打开下方实际LOD阶段；不能将错误来源直接传给下一步。

相同来源重复点击复用未修改草稿；已修改或已运行的草稿不覆盖、不再创建，并提示查看已有节点。创建或保存失败不会启动模型计算；页面保留草稿，原来源再次点击可重试保存。

检测和已支持的局部边界重拓扑由画布后台算法自动执行。完成修复的正式结果提供“查看局部修复对照”：根据保存的真实修复记录、最终模型及可逆面映射重建修改前几何，验证前后身份后生成整体位置与同视角局部对照。对照按需生成并缓存，不重算高模或减面，不依赖Agent拼图。橙色表示认证未完成，绿色表示已通过修复；编号分别属于前后网格。

当前支持单个外边界区域的有界算法修复与只读对照，尚未提供自由框选区域的手动重拓扑编辑器，也不保证任意破面都能自动修好。

部署状态：已在用户刷新后的当前画布验证LOD4/UV切缝草稿创建及正确连线，重复点击复用原草稿；保存版本331，原36个节点数据未改变，没有新增计算任务。正式修复对照接口身份核对通过，未由Agent点击弹窗。未上传发布。

## 2. 用户手动操作

1. 在“3D模型”导入FBX/GLB/OBJ，看到实际面数、材质/UV状态、格式支持提示。展开3D检查结构和方向；高模用明确标记的预览代理，生产输入仍为原模型。
2. 连接“LOD分级”，选择“传统LOD”和“原高模保形”，检查各档保留比、基准、预计面数和预算，点击“生成分级”。按实际完成档位显示LOD0–4，不拿缩略图代理当生产LOD。失败保留上一档，不继续传递错误结果。
3. 选择要分UV的档位，接到“分区与切缝”；原高模接其“高模参考”。选分区方式、粗细程度和AO辅助，点击“分析切缝”。
4. 打开3D工作区，旋转/缩放查看分区、AO和候选缝。可重新调粗细/合并阈值；直接点选边增加/删除可编辑候选缝列为编辑能力，不用图片画线替代真实拓扑。已有开口、必要拓扑边及不允许删除的约束明确区分。
5. 确认本次切缝计划，将计划输出接入“UV展开”；选择分辨率、间距、方向和拉伸容忍度，点击“展开UV”。只有这里才运行展开与排布。
6. UV结果在3D棋盘与2D图集联动检查。标出新增算法切缝、微小岛、拉伸和利用率。需要调整时回到切缝计划，创建新版本；保留旧结果，不能悄悄用新参数覆盖旧确认。
7. UV模型接“材质烘焙”的低模口，原高模/原材质接独立高模口，选择4K、通道与质量，点击烘焙。投射遗漏、对应歧义或源法线无效分别显示，不用中性色填充后标成功。
8. 双击结果进入3D材质检查，切换灰模/完整材质/单通道。导出完整材质GLB，以及FBX几何+UV+法线和独立贴图。FBX的材质自动映射及目标引擎切线需独立验证。

Agent与用户走同一任务、参数校验和质量门；不要求用户手工填写本地路径、缓存JSON、任务ID或脚本。结果必须通过当前画布页面保存和连线。

| 材质烘焙 | 高低模已连接提示、2K/4K、法线/AO/颜色/粗糙度、生成 | 自动投射距离及实际值、采样、边缘扩展、OpenGL/DirectX法线约定 |
| 结果 | 面数、贴图尺寸、检查状态、打开3D、下载 | 独立通道、原高模对照、实际来源与参数快照 |

“少碎片”表示连续区域整合及可承受拉伸，不是删掉小面。“尽量方正”服务于排布利用率，不强行把所有岛拉成矩形。普通参数用中文和明确单位，原始调试字段收在诊断中。

## 4. PartField、AO与切缝的关系

真实链路为：原高模表面采样 → PartField神经特征 → 特征聚类建议 → 映射到目标LOD并整合连续区域 → AI边界 → 目标LOD的凸角结构 → 凹角结构 → 有映射高模AO支持的凹槽补缝 → 候选缝 → 用户确认 → 展开新增必要拓扑缝 → 排布。结构角度来自实际目标几何，不冒充逐高模面角度推理；高模AO与AI证据仍绑定原始高模。

高模身份与特征缓存固定，调整区域数可复用已算特征，不反复加载权重。目标LOD改变只重做映射和计划。不得把低模特征或屏幕法线块面冒充高模PartField。显示高模采样点数及未覆盖/低支持区域；不把32768个采样点宣称为100万面逐面识别。

整合优先处理面积很小、狭长、边界锯齿的连通区域，结合邻接长度、特征相似度及凹槽证据选择合并方向；不把远离的同色区域强行当成一个连续UV岛。未知区域不能无条件成为合并两个明确区域的桥。AO暗部作为优先候选而非每个黑点都切缝。分区数不等于最后岛数。

目前本机PartField接入是研究执行器，不是正式通用能力。已读取本机源码LICENSE第3.3节：限制为非商业研究/教育用途，不能默认作为已获商业许可的产品功能。发布前分别核对源码与权重许可及可用替代执行器；固定runner和真实GPU占用协调必须产品化，不能用任意“租约字符串”冒充资源锁。

## 5. 3D工作区与性能

画布卡片保持4:3静态概览，双击/“检查3D”打开同一按需工作区。避免每个节点常驻WebGL、同时上传高模及多套4K纹理。关闭释放模型、纹理、事件和渲染循环；切换来源取消旧加载。

工作区：中心可旋转模型，右侧参数与图层，底部“重新分析 / 确认切缝 / 展开UV”。展开后增加2D图集面板。图层至少灰模、分区色、AO、候选缝、最终缝、棋盘、材质；候选缝与额外拓扑缝不同颜色和图例。

切缝审查必须加载与目标LOD一致的真实拓扑或经过验证的精确映射，不得拿任意减面代理画缝。100k以下目标采用有界加载和线段叠加；大高模分析只显示带明确标识的代理或真实采样点。生产AO/特征/烘焙继续使用高模，不因浏览器优化替换源数据。

## 6. 两阶段计划的数据约束

新增uv_plan操作，禁止调用xatlas、展开或打包。计划包含不可变高低源hash、参数版本、特征与AO依据、候选真实边、未知区域、资源统计及计划hash。大数组用有界产物引用，不塞进现有64KiB请求或28KiB证据文本。

用户确认绑定计划hash。更换输入、模型变换、分区/切缝设置、手动边编辑或影响展开的参数后，确认变旧；后端在提交及执行前复核，返回明确UV_PLAN_STALE，不依赖前端勾选。UV只消费被确认计划，不自行重做另一版AI分区。

展开为避免翻转/重叠可能新增切缝，必须另列“算法新增”，不得宣称确认候选缝与最终缝必然完全一致。候选计划没有UV，因此不能显示虚构最终岛数、棋盘或最终利用率。
