## 手动局部修复按钮（1.1.42）

边界检查未通过的LOD卡片和诊断窗口新增「尝试局部修复」。点击后，画布创建并保存独立修复节点，再提交后台任务；输入绑定该失败任务的最终候选文件、网格哈希和原高模。保留原候选，不从父LOD重新减面，也不重跑整条链。重复点击复用同一尝试；保存失败不提交计算，交付失败优先重新交付。

首版采用有界传统算法：最多处理4个不同原始面的局部边界，最多增加4个三角面，仍受用户明确面数硬上限和父LOD面数约束。减面软目标不再阻止必要的小范围加面。单处位移仍不超过模型对角线的0.002，原有边界、相交、法线及形状检查保持；不支持所有类型的网格错误。修复成功才开放UV等下游入口；未通过保留原候选与定位证据，明确提供「返回原候选 / 保留更多面」，不会自动反复重试。

真实超限的合成样例修复通过。当前岩壁最新LOD4离线尝试约8.67秒，由于需要的局部位移超过保护范围而未通过；没有把它标为修复成功。旧自动修复的保护策略未改变。新版手动修复的详细报告和标记可检查，旧版自动修复对照图接口尚不覆盖新版手动流程。

部署状态：后台测试、独立审查与隔离界面验证通过；本地服务已加载新版并核验修复参数接口。当前页面刷新后可使用按钮；尚未提交新的真实画布修复任务。未上传发布。

## 问题确认后的处理引导（1.1.41）

“检查确认”只说明问题真实存在，不代表已经修复。失败LOD卡片与诊断窗口现在同时说明失败原因、可操作的下一步以及当前修复状态。

对于本档外轮廓偏差超限，可选择“创建调整草稿”：默认建议在原保留比例上增加20%，也可修改比例；以原LOD0为百分比基准，从已验收的直接父LOD重新减面当前档。当前LOD4示例为1.25%（1249面）调整至1.5%（约1499面）。草稿自动连接正确父模型和原高模，换新种子，只创建并保存，不启动计算。用户检查后点击生成；通过后再使用“制作UV”等后续入口。

这不是当前候选的局部修复，也不保证一次通过。几何质量阈值保持不变；目标必须低于父级面数且不突破已有硬上限，没有增加空间时说明原因并禁用。重复点击复用未修改草稿，已修改/运行的草稿不覆盖；保存失败可重试保存，不重复提交计算。

本例1249面候选的确认偏差为130.006 mm，允许81.389 mm，完整自交检查为0。有限局部修复试验仍未通过独立边界检查，未接入正式结果，也未提供误导性的“一键修好”。现有已支持的自动局部修复仍按原能力运行。本轮未重算其他LOD，未上传或发布。

部署验收状态：独立审查及回归通过；用户刷新后已在当前画布创建并保存「LOD4 · 调整减面比例」，1.5%、新种子4286422903，正确连接已通过LOD3与原高模。重复动作复用同一草稿；40节点/56连线，原39节点数据不变，无新计算任务。调整后是否通过仍待用户手动生成验证。

## 1. 产品边界

- 在画布后台完成独立3D资产处理，不要求用户安装 Blender 或依赖 ComfyUI。Blender可作自选外部对照工具，不作为必须的执行器。
- 面向高面数扫描模型、AI生成高模和已有UV/贴图的高模。FBX是重要导入导出格式，同时支持实际已验证的OBJ、GLB路径；格式不等于材质、法线均已正确保留，必须检查。
- 正式节点使用通用命名，方法在节点内选择；记录实际算法、版本、预设、种子、输入、时间及面数。不能将传统减面标作AI减面。
- 当前岩壁实际减面使用Open3D/PyMeshLab传统算法；PartField是分区辅助AI。UV展开与烘焙是算法。MeshAnything作为已有其他测试路线，不能据此声称当前岩壁由它执行。

## 2. 导入与基础检查

导入高模和材质贴图，保留原件、坐标/单位、法线、材质槽、原UV和贴图来源。检查是否为开放表面、原有缺陷和材质通道，区分真实错误与正常开放边界。原高模有缺陷不应在后续笼统归咎于减面。

原高模供几何分析、形状对照与烘焙；轻量代理供交互显示，两者不可混用。画布默认4:3缩略卡片，双击3D查看器按需加载，支持缩放；不同时加载所有LOD和4K贴图。后台分块处理、资源调度与缓存复用均需单独验证，尚不能承诺千万面耗时/内存。

## 3. 逐级LOD制作

来源关系：原高模 → LOD0 → LOD1 → LOD2 → LOD3 → LOD4。每档对照不可变原高模检查；重做失败档从其已接受父级开始，不重新生成已通过的上游档位。下游若已存在，标记来源过期，不静默混用。

面数目标的百分比基准与几何输入来源分开：既有设置LOD0相对原高模、LOD1–4相对LOD0，不能因几何链逐级连接就悄悄改成相对上一级。UI明确“保留/减少”“相对谁”“预计三角面数”。LOD0可用于本项目Nanite候选；10万面是本项目预算偏好，不是UE/Nanite通用标准。

待开发自适应策略：自动/AI重拓扑/传统抽面可选；面数软目标与显式硬上限分开。允许范围内尝试少量不同目标或备用算法，同一失败档最多三个有效候选、共享总时间预算、通过即停。实际目标被硬上限裁成相同数值时必须去重。用户明确硬上限不能被静默突破。具体预算须测试，不承诺未经验证的秒数。

传统抽面优先边折叠；平面溶解用于合适的平坦结构，反细分用于规则网格。改变算法必须记录真实方法。单档重试现已增加一次有总时限的传统抽面回退，代码和真实父级候选均通过独立检查；仍需正式画布任务验证。它不等于以上完整自适应调度，软目标/多候选去重尚未实现。

## 4. 局部修复与质量分级

先尝试已有的有限局部几何修复：调整三角连接或小幅移动内部顶点，保留外圈与原高模形状约束。这是算法，不是AI。

完整局部重拓扑尚待开发：仅取问题区域加过渡圈，固定接缝边界、内部重建并贴合高模，必要时增加局部面数；完成后检查与外围连续性、形状和法线。不能把凹槽直接补平，也不能声称已有稳定实现。

分级原则：文件损坏、非有限坐标、明显新增孔洞/翻面/严重交叉等阻止自动进入正式下游；合理面数偏差、单纯边界边数/周长变化和轻微误差给出提示，结合轮廓与实际影响判断。继承源缺陷与新增缺陷分开记录。不用一个过严统计阈值拒绝所有结果，也不靠平均指标掩盖严重局部错误。失败候选仍应可见、可检查，不默默丢弃。

## 5. 原高模结构分析与切缝

使用原高模进行PartField分区和AO/结构分析，复用缓存，再映射到接受的目标LOD。高模代理仅显示，不冒充分析输入。

顺序：AI大块分区 → 持续的凸角转折切分 → 凹角与AO辅助补充 → 合并过碎区域 → 预览切缝。AO深色不一定都是应切位置，平滑噪声和细碎三角不应生成大量无效切缝。

画布必须分别展示分区、AO、角度切分、最终切缝。目标LOD上可检查3D接缝后再展开，不把不同过程全部显示为同一张海报。其他LOD优先复用高模分析，不重复推理；映射仍需检查拓扑适用性。

## 6. UV展开与跨LOD策略

先在已确认切缝上自然展开，再统一岛间纹素密度、整理朝向和排布。允许一定拉伸，以少碎岛、较高利用率为目标；“方正”是为了利用率，不是把每个岛强行拉成矩形。

展示真实UV图集、表面棋盘和接缝，明确利用率、密度差异和拉伸热点。轻微拉伸不挡住结果预览；重叠、翻转等实质问题清楚标记。用户检查结果再决定是否调整。

原高模有可用UV/材质时，优先评估属性保留或表面映射；拓扑变化后不能保证UV不变。LOD间有两条合法路线：保持可验证的共同UV/材质映射以共享贴图，或对无法可靠继承的LOD独立展开并由高模重烘。不得假称所有LOD都必须重分UV，也不得承诺所有LOD无条件共享同一图集。当前独立展开/烘焙路线存在，可靠跨LOD UV继承仍需实现与验证。

## 7. 4K材质转移与烘焙

输入必须是实际带UV的目标LOD和不可变原高模材质来源，不能用显示代理或低模替代高模。

区分原始贴图转移与几何新烘焙：BaseColor、Roughness等从原材质映射；Normal结合几何细节和可用源法线；AO依据选择使用源贴图转移或几何计算，并记录真实方式。源材质已有AO转移时，不声称重新发射AO采样射线。未知法线方向不能宣称已确定。

最终4K指实际4096×4096贴图。检查投射漏点、凹槽误投、接缝、法线方向、padding和最终材质预览，不能仅提高采样数解决投射错误。局部修补/局部烘焙若尚未实现则不得承诺已可用。保留不支持通道的原文件，不声称全部八种源贴图都烘焙完成。

## 8. 检查、导出与画布交付

每一步计算完成后保存真实结果节点，并显示当前阶段。状态至少区分：计算中、计算完成待保存、已保存、待检查、失败；“任务执行完成”不能与“几何通过”混为一谈。

导出模型和贴图，记录各LOD来源/实际面数/使用方法。FBX回读验证几何、UV、法线；材质自动绑定未验证时明确提供贴图和绑定说明。GLB可用于完整预览，另提供适合UE的法线与通道约定，避免方向误用。

画布保存失败时，计算文件保留，仅重试交付，不重算。恢复入口必须一直可见；保存版本冲突不得自动覆盖其他页面。显式保存重试与连接误报分离已加载；本轮LOD1恢复交付、LOD2和LOD3自动交付成功。长期稳定性仍需继续观察。交付报错还需明确文件名及失败阶段，禁止为保存错误重烘。
