最新用户决定：Nanite复用最终LOD0的同一模型、UV及材质，不再另做独立源高模输出。原始高模始终作为分析和贴图对烘参考。当前新增百分比减面、独立切缝规划、共享3D预览和确认后展开的实现正在验证；新项目及4K结果交付以真实画布节点、素材和保存版本为准，不能以代码完成替代。

用户指出花岗岩从1,000,024面直接到AI候选1,772面，不能作为完整资产分级。旧1772→1200→800→500→300仅为AI极低模试验，保留作对照，禁止继续当成新规格的LOD0–4或把它升面冒充高档模型。

传统LOD改用明确基准的保留百分比，结合形状/轮廓/UV误差、屏幕占比与可选面数预算。原高模→LOD0的比例单独设置；后续显示相对LOD0及相对前一级的实际保留比。100/50/25/12.5/6.25可作可编辑的温和起点，不是行业强制标准。本例此前LOD0≤100000、LOD1≤10000仍作为预算约束记录，用户可显式修改；与比例目标冲突时显示有效保留比，不静默覆盖。旧100000/10000/3000/1000/300不再作为所有资产默认表，LOD4不固定300。源高模不变、输入低于目标不升面；逐级生产实际来源可追溯，但拆多步不等于保证保形。

MeshAnything作为独立AI低模候选保留；高档LOD使用明确标注的原高模保形几何减面，不声称传统算法为AI，也不替换用户已有AI节点。保形、孔洞/部件/开口和材质来源由实际质量检查约束，不因达到面数而自动验收。

PartField是真实高模采样特征与分区建议，必须可见显示来源、采样预算、版本/权重身份、耗时、缓存复用和失败。分区不等于UV岛；避免将所有分区边界或AO暗点设成硬缝。少碎片、拉伸、图集利用率、密度、方向与新增拓扑切缝共同验收。

手动主线固定为“模型导入 → LOD分级 → 分区与切缝规划 → UV展开 → 材质烘焙 → 结果检查/导出”。高模以独立参考输入连接规划和烘焙。先在按需打开的3D工作区旋转检查分区/AO/候选缝，确认后才展开；预览阶段禁止暗中运行xatlas后再称作预览。输入或参数变更使确认失效。节点保留4:3静态概览，不能为每个节点常驻一个WebGL视图。

新增输出目标“传统LOD / Nanite准备 / 两者”。Nanite静态网格不套固定五档传统LOD，不存在官方统一最佳面数；优先保留有用的源细节及已有UV/材质，按实际UE版本和场景测试Keep Triangle Percent、相对误差、切线和Fallback。材质UV与Lightmap UV分别处理；不使用预计算光照时不强制生成Lightmap UV。具体来源及参数见 [LOD与Nanite制作依据](LOD_NANITE_AUTHORING_RESEARCH.md)。

详细参数、交互、边界与实施顺序见 [手动3D制作与UV确认流程](NATIVE3D_MANUAL_WORKFLOW.md)。本修订是新的实现依据，不表示新分级或完整手动界面已经交付。当前几何精确检查上限10000面、UV试用输入上限20000面是需要改造的实际限制，禁止直接调高数值后假称可用。

### 接续执行检查（1.1.8起强制）

#### 高模识别源与成本门（1.1.15）

1.1.16执行补充：用户已接受当前约200万面的成本，结构证据以原始高模为准。UV仍在经修复、贴合的LOD0上展开；高低源文件哈希和原面顺序同时绑定。高模查询点的AO采用完整几何遮挡计算，不能复用正面诊断图冒充全表面数据。投射按距离、法线及多点投票一致度设支持门；不支持面保持未知，不强行赋予神经标签。未知区域的几何展开允许有记录的拓扑回退，但不得成为合并两个已识别不同高模分区的桥。

千万面资源规划：按200万面测试估计，固定采样预算的1000万面AO诊断约1–2分钟/3–6GiB，AI分区及回投约2–4分钟/建议预留6–12GiB；推理CUDA预算约1–2GiB。以上不是实测或完整UV/烘焙总耗时。当前高模保护门仍为300万面，支持千万面须先补流式读入、分块/缓存、预算中止和实机测量；如提高采样精度需重新估时。浏览器继续只加载轻量代理。针对凹槽/未知区域的自适应加密属于后续优化，不假称本轮已经实现。

- 1772面LOD0虽然可作为游戏低模/UV目标，不能代替原始约200万面岩石的凹槽、AO和大块面识别源。向高模发射遮挡射线但仅从低模面心取样，也不能称为完整的高模识别。
- 原始高模保持几何和面序，不先减面。AO先用完整高模构建加速结构，再在高模真实表面采样。诊断图明确相机、可见范围、样本预算及显示分辨率；正面AO预览不是完整表面AO烘焙。
- AI分区从完整高模表面按面积抽样。为8/12GB设备控制编码/查询总预算、分块处理；明确记录覆盖率、插值/投射规则和失败区域，不把少量样本投射成的全网格标签称作逐面神经推理。
- 同一高模坐标、相机、随机种子和采样预算与低模对照。分别计量读取、BVH/采样、模型载入、推理、聚类、投射和导出；报告端到端时间、进程树内存、CUDA分配峰值，整卡后台显存另列。新增高模证据不自动覆盖既有UV或宣布分区验收通过。
- 角度连通或聚类产生的分区必须先审图；无法保留合理凹槽边界时标记失败/待复核。高模证据通过后，才映射到LOD0及后续LOD，并继续检查UV密度、岛数、方向、拉伸和利用率。
- 模型节点静态图片双击打开大图，滚轮围绕指针缩放、拖动平移，提供适应窗口/100%和比例显示；弹层滚轮不传给底层画布，关闭后清理交互状态。

每次接续任务先对照本节与实施记录，不用压缩摘要或上一轮“已跑通”结论替代主计划。当前实施缺口必须明确保留，不能改写成未获用户同意的未来范围。

- AI候选分支必须具备：原始AI候选 → 局部修复 → 朝向校正与受约束贴合 → 从前一级递减的LOD链 → 所选LOD的UV → 材质烘焙 → 导出。仅统一面朝向不等于完整局部修复和贴合。1.1.20新增的原高模保形分级分支独立执行，不强制先生成AI极低模。
- 每阶段记录输入/输出哈希、算法、参数、实际面数、质量报告及实际预览。阶段失败就保留失败候选并停止自动推进；调试性下游试算须显式标记，不能成为正式交付。
- 不能把原始AI候选直接展开UV、烘焙的基础通路称为计划版完成；不能把一次性简化或分别从基底减到多档冒充连续LOD。
- 交付包含FBX格式回归、连续LOD来源核验、结构切缝/UV检查和相同机位阶段对照。缺任一项时明确未完成。
- 2026-11-03的1933面岩石试用保留为失败/调试证据，不作为新的质量基线；历史1766→1772→1200→800→500→300案例为算法复现参考，不复制历史模型冒充新任务输出。

### 同一案例复刻验收（1.1.9）

- 本轮用户要求先验证无 Blender 的减面复刻。以已重新推理、与历史 token 一致的1766面AI候选为输入；执行原记录的T接缝修复及两个指定补片，得到1772面基底，再贴合和连续LOD。不得用历史最终模型冒充本次输出。

## 1. 产品目标与本版边界

### 1.1 面向的输入

面向扫描、人工制作和 AI 生成的**高模**，优先验证静态岩石、岩壁、场景块面和非变形道具。不能假定 AI 高模已经干净：可能存在重复面、分离部件、内部面、孔洞、错误绕序、非均匀缩放，以及带固定光照的底色图。

用户在同一画布完成：

**导入高模 → 查看与检查 → 原高模保形LOD（或独立AI低模候选及修复/贴合分支）→ 分区与切缝确认 → UV展开 → 烘焙 → 完整材质结果 → 导出。**

首要目标是保留形状和来源、得到可检查可修改的低模与材质成果，不能只以脚本退出成功作为完成标准。

### 1.2 必须保留的方向

- 保留 **MeshAnything V2 + 后处理 + 连续 LOD** 的AI候选适配基线；资产分析、接口和下游不得写死该模型或岩壁案例。1.1.20按新高档面数规格新增独立原高模保形分级，明确标注几何算法；不替换已有AI节点、不把两种路线混称AI。
- 传统减面可保留为显式可选工具；AI 失败不自动切换到传统算法。
- UV 与烘焙属于本目标版本的完整交付范围，不永久推迟为另一个未定义项目。
- 节点封面和阶段总结用直观图片；3D 查看按需打开。几何阶段看形状、轮廓、线框；完整贴图在 UV 与烘焙之后展示。
- 复杂的 Blend、多材质混合、程序噪声编辑器和 AI 材质变体**暂不纳入 1.1.0**，后续单独设计，避免把首版做成复杂材质编辑器。

### 1.3 首版不承诺的能力

角色动画变形布线、骨骼、植被薄片、任意多部件批处理、任意分辨率/面数、UDIM、自动生成完整物理真实 PBR、从单张底色可靠恢复全部材质属性，以及所有硬件上都能加载任意高模，均不属于首版默认承诺。

多物体、多材质、UDIM 必须被识别并显示；未支持的情况明确阻止相关阶段，不默默只取第一个对象、第一套 UV 或第一种材质。

### 1.4 产品定位：画布自己的 3D 制作能力

这条流程是 Refmuse 画布原生的 3D 资产制作模块，由本项目开发任务编排、模型资产管理、几何处理适配、UV/烘焙流程、结果检查、交互与导出。原先“单独制作 Blender 插件”的方向扩展为“在画布内完成制作全过程”；TopoForge 插件与研究成果是可复用的实现基础，不是用户必须进入的另一套主界面。

用户在画布导入、设置、提交、取消、查看进度、选择版本和导出。正常受支持的完整流程在画布后台执行，不要求用户打开 Blender 窗口或 ComfyUI 页面。人工修缝、局部几何修正等外部精修作为可选操作，不是正常流程每一步的必经入口；遇到不确定结构需要人工处理时，明确停在待复核。

“自研”指产品与流程由本项目实现，不表示 MeshAnything 权重或第三方几何库是本项目原创；各依赖的身份在环境和任务记录中保持清楚。

### 1.5 执行架构：3D 引擎独立于 ComfyUI

```text
Refmuse 画布：节点 / 项目资产 / 状态展示 / 保存
                 │
         画布后台服务与鉴权
                 │
       ┌─────────┴──────────┐
       ▼                    ▼
原生 3D 任务服务       图片/视频任务适配
  ├─ AI 推理执行器            └─ ComfyUI 等既有后端
  ├─ 几何/LOD 执行器
  ├─ UV 执行器
  └─ 烘焙/导出执行器
```

3D 任务拥有自己的 jobId、队列、进度、取消、恢复和结果清单，不通过 ComfyUI 的 prompt、节点注册、history、文件输出目录或模型列表完成处理。复用的是画布的 UI、资产、鉴权与保存能力，不是对 ComfyUI 工作流再套一层按钮。现有 H3PACK 图像工作流协议不承担任意 3D/Python 程序执行。

画布后端需将“服务在线”“3D 引擎可用”“图片/视频后端可用”分别判断：即使未安装或未启动 ComfyUI，3D 模块也能在自身依赖齐备时导入、预览、计算、保存和导出。ComfyUI 离线不能让整个画布显示为不可操作，不能阻断 3D 队列。

增加明确的 3D 独立启动/安装路径：只使用 3D 时，不强制安装现有 `core-h3` 模型包，不为执行 3D 自动启动 ComfyUI，也不把“8188 端口就绪”当成画布或 3D 的启动条件。配置允许用户同时启用两类后端，保留既有图片/视频用户的已选择启动行为；不能为新增 3D 擅自改变其设置。启动器、环境检查、Agent 接口、按钮可用性与错误提示都要跟随这套能力拆分。

### 1.6 完全脱离 Blender 的实施目标

受支持的完整流程不要求下载、安装或启动 Blender，不捆绑 Blender 二进制，也不通过 pip 安装 `bpy` 绕过这一要求。1.1.1 的后台 Blender 过渡方案被本修订取代。TopoForge 现有案例仍是算法与结果基线，但依赖 `bpy`、`mathutils`、Blender BVH/操作器的实现必须拆出或替换，不能声称现有插件已能独立运行。

推荐组合：独立 PyTorch 环境执行 MeshAnything；提取现有修复/贴合/QEM LOD 算法；trimesh 负责首版 GLB/OBJ 适配，meshoptimizer 用于显示代理；xatlas 提供 UV 基础；Open3D 做 CPU 几何查询原型，Embree 作为可评估的正式射线后端；自研高低模烘焙流程并使用 MikkTSpace 保持切线一致；Three.js 负责画布查看。组件选型不等于全部默认安装，按实际验收保留最少依赖。

独立烘焙需实现 UV 光栅化、Cage 投射、正确表面命中、源 UV/角点法线/材质插值、Normal/AO、通道转移、扩边与质量报告。Open3D/Embree 都不是开箱即用的完整材质烘焙器。MIT 的 BakeForge 可作为 Windows DX11 法线模块候选，AO 与扩边尚未完成，不直接替代完整流程。

产品使用独立、可校验的 3D 运行环境，不借用 ComfyUI 或系统 Python；AI 环境与轻量几何/UV/烘焙依赖分包。用户可在画布按需配置组件，具体自动下载与安装实现另行验收。用户无需学习或操作这些开发库，但运行资源、下载体积与模型许可仍须如实呈现。

先完成 [脱离 Blender 的组件研究与验证门](BLENDER_FREE_3D_RESEARCH.md)，再接完整产品。外部 DCC 精修只作为可选互操作；原生 `.blend` 读取/保存不属于无 Blender 首版范围，源文件需要在原创作工具中导出 GLB/OBJ。现有 Blender 工程继续只读保留，不能为迁移自动改写。

### 1.7 Agent 根据当前模型动态选参数

推荐设置必须依据当前模型、用途、质量约束和资源预算，经过检测→有限试算→对比→调整→正式验证；固定预设只作起点。对外称“当前预算内已验证推荐”，不把未经验证的参数或有限搜索包装成全局最优。测量和安全限制由服务端执行，Agent 根据报告与局部证据选择参数；用户锁定的设置不能静默改动。

复用现有 MCP 的 state/query/apply/wait 与当前页命令通道，扩展 3D 语义，不另起项目写入者。专用 Skill 负责判断与操作流程；参数规划器和质量检查器由画布后台提供，无 Agent 用户也能一键推荐。能力独立于 Blender/ComfyUI，不能继承旧启动检查对 8188 的硬依赖。具体职责、参数依据、预算、接口与验收见 [3D Agent 动态参数设计](AGENT_3D_PARAMETER_PLANNING.md)。

### 1.8 通用节点与模型适配

同时支持“换输入高模资产”与“换AI执行器/权重”：新资产先分析结构、单位、部件、源UV/材质并推荐参数；新执行器通过注册表、参数schema与标准结果协议接入同一个AI低模节点。下游修复/LOD/UV/烘焙不因换模型重建节点链。精确设计与验收见 [通用3D节点与适配器](3D_NODE_ADAPTER_DESIGN.md)。

公共制作目标、模型专属参数、本机环境三层分离。部分参数需提前绑定对应权重和依赖，另一些由当前资产动态推荐；所有参数在后台验证。不同模型的采样点数、token/体素/量化、steps等不能机械互抄。新架构需要适配器，不能把“下载权重”自动等同“支持该节点”。

至少两个不同真实后端的完整对照列为跨模型验收项；仅测试一个后端或协议替身时明确未验证。现有模型、输入和结果仍保留，切换失败不能清空旧成果。模型特有控制与后处理达到的制作目标分别归因。

### 3.2 模型节点如何显示

- 默认显示静态 WebP 封面，长边 640px，复用现有可见区域加载与缓存思路。优先验证受控离屏 Three.js 渲染任务，与查看器共用材质/相机；Windows 无界面渲染需实测。封面任务失败可重试，不引入 Blender 回退。
- 下方显示资产名、实际三角面数、单位/尺寸、当前版本，以及 UV/材质状态；注明“源高模”或“低模结果”。
- 双击打开当前画布内的单个 3D 查看面板；右键提供“查看报告”“导出”“导入外部编辑版本”等操作，不依赖特定 DCC。
- 高模查看默认加载**显示代理**，明确标“代理预览”；显示的原高模面数与当前代理面数分开，不能把代理当原件。
- 查看器提供旋转、缩放、实体、线框、棋盘格、高低模切换；完整材质完成后再开放通道单独查看。
- 默认一次一个活跃查看器。高低模对比共用同一 renderer/context，必要时顺序切换，不创建几十个 WebGL 实例。

### 3.3 阶段总结图片

几何总结：原高模参考渲染、AI 原始候选、修复/贴合、各档 LOD；相同相机、比例和光照，标实际面数和检查结论。

材质总结：完整材质的模型效果为主，附真实 Base Color、Normal、AO、Roughness 等通道及其来源。失败区域另作诊断图，不把法线蓝图当作完整成果封面。

封面、总结和模型/UV/材质版本绑定；上游改变后标旧或重新生成。总结板是派生文件，不能取代真实模型和贴图资产。

## 4. 资产分层：优化显示而不损坏制作依据

| 层级 | 内容与用途 | 使用约束 |
|---|---|---|
| 源资产 | 用户原模型、原贴图、材质与依赖清单 | 不覆盖、不简化；保留来源内容哈希 |
| 处理快照 | 本次任务实际使用的几何、变换、法线和材质状态 | 不可变；修改生成新版本；必要清理有记录 |
| AI 输入派生 | 归一化、朝向转换、MC/采样等模型预处理 | 记录全部转换与逆变换；不冒充源表面 |
| 显示代理 | 低成本可旋转几何、缩小贴图 | 只用于显示，不能自动用于质量验收或烘焙 |
| 制作结果 | AI 原始候选、修复、贴合、LOD、UV、Cage、烘焙贴图 | 明确父级、版本、状态与哈希 |
| 展示缓存 | 封面、对比板、浏览器代理文件 | 可重建，按容量淘汰，不当源文件删除 |

代理损失细节不代表原模型损坏。烘焙默认引用原高模或明确指定的处理快照，禁止为了省内存悄悄改成预览代理。确实需要轻量烘焙源时，必须作为用户可识别的独立制作选择，并重新记录和验收误差。

## 5. 制作步骤详解

### 步骤 0：环境与资源预检

**输入：** 画布原生3D引擎配置，以及当前所选执行器需要的独立几何/UV/烘焙组件和AI运行环境；MeshAnything为首个适配基线，不是所有节点的必装依赖。Blender、ComfyUI均不属于必需环境。

**操作：** 检查可执行文件、版本、模型严格加载所需依赖、权重哈希、可用 RAM/VRAM/磁盘，以及当前运行任务。

**输出：** 能力报告，分别标 AI、几何、UV、CPU/GPU 烘焙是否可运行。

轻量几何执行器与 AI 私有 Python 分开，不改系统 Python，不借用 Blender/ComfyUI 环境。记录现有 Windows SDPA 适配，不能称与官方 FA2 已逐位等价。只使用项目已有或用户明确配置的依赖，不自动下载权重。

资源不足时排队或说明缺失；不自动停止 ComfyUI、不卸载他人模型、不强制中断用户 Blender。检查通过只表示环境可用，不代表模型或材质质量通过。

只检查当前启用的 3D 执行器依赖。不存在 ComfyUI 时也能完成本步骤；其他应用是否占用 GPU 通过资源监测判定，而非要求安装一个 ComfyUI 服务来查询资源。

### 步骤 1：导入高模与依赖

**入口：** 拖入文件或右键“导入模型”。FBX为主要游戏资产交换格式，GLB、OBJ同时支持；FBX导入与导出是本版交付要求，不再列为可随意延后的补充项。内部可使用GLB作为轻量显示缓存，但不能要求用户用GLB代替FBX交付。独立格式适配器必须验证单位、坐标轴、对象变换、三角化、角点法线、UV、材质槽及贴图引用，并执行导出再导入回归；不通过改扩展名假装FBX支持。未实现前界面如实显示未支持。`.blend`提示从原创作工具导出受支持格式，不启动后台Blender转换。

后端接收文件并计算哈希，生成元数据；浏览器不先解析完整高模。多物体列出对象、面数和材质状态，让用户选择；不默认合并或丢弃部件。

GLB 内嵌资源、OBJ 的 MTL/贴图需要统一依赖清单。原件与可获得的依赖纳入项目快照；缺失、外部、不可转换材质明确显示。不得自动访问任意网络 URL 或项目外未知路径。解析采用受控子进程、文件白名单和资源限制；这不是完整 OS 沙箱。trimesh 适配需禁用隐式合点等处理，保存场景实例和变换；材质支持按实际往返测试列出。

记录坐标轴、单位、对象变换、包围盒、几何计数、材质槽、UV 层、平滑标记、角点法线和源贴图。输入只有灰模也可继续，但显示“无原材质”，不能暗示后续能恢复不存在的表面颜色。

导入时同时识别“源 UV 存在/有效”“源贴图齐全”“各通道引用的 UV 集/变换”“原材质可解析”四项，不能只凭存在 UV 层就判定材质可转移。有 UV 的原高模不重新展开，原 UV、材质关联与贴图均进入只读快照；后续低模重新展开不会覆盖它们。源 UV 的镜像/重复/跨 0–1 平铺可能是有意设计，按源采样规则处理，不能直接套用目标独立烘焙图集的无重叠门槛。

**验收：** 原件哈希不变；中文/空格文件名可用；依赖不丢失；重复导入去重；取消上传不生成有效资产；刷新后仍能找到原件。

### 步骤 2：后台检查、封面与显示代理

导入后先显示轻量占位卡和真实阶段。由独立后台进程读取模型、检查有限坐标/索引/容量并生成代理及封面。元数据暂缺时显示“检查中”，不用占位数伪装实际面数。

检查重复/退化面、非流形、开口、连通部件、尺度与朝向。开放岩壁允许存在预期外轮廓；不能把所有边界都当孔洞填掉。AI 高模常见多部件、浮动面和粘连必须报告。

轻量预检与全量几何审计分开标记。代理不能承担全量原件自交检测。需要长时间或高内存的检查单独排队并显示阶段，不阻塞画布操作。

清理只操作副本，记录删除/合并/变换范围及影响；无法确定结构意图时标待复核，允许外部工具精修后导入新版本，不默认破坏性修复。

**输出：** 原模型元数据、检查报告、代理、封面。原高模不可加载时允许保留已上传文件和错误信息，不标“导入完成且可处理”。

### 步骤 3：AI 生成低模候选

选择高模与已就绪的兼容执行器，默认一个候选。执行器schema声明所需输入、预处理和解码配置，先按本资产分析结果检查适用性。MeshAnything基线在通过检查后使用已验证MC256 profile、8192点及严格权重加载；这些值不作为其他模型默认。开放岩壁、薄片或偏移会合并间隙的输入先复核，不适用且没有已验证替代路径时停止自动生成。历史案例通过不代表任意同类输入可直接处理。种子、采样等按模型放高级选项，实际版本与配置明确显示。

目标三角面数属于公共制作目标，适配器另声明原生控制为无/近似/精确及其单位和条件。MeshAnything的目标几百面由后续LOD尝试达到，不暗示神经模型精确控制；其他模型也不能把顶点数条件冒充面数。不得在失败时悄悄换成原高模传统减面，也不能用历史岩壁成品充当新输入结果。

阶段为：准备输入 → 预处理 → 加载模型 → 推理 → 解析候选 → 检查。没有真实总百分比时不显示虚构百分比。记录推理耗时与端到端耗时，测量峰值资源并说明采样方式。

适配器支持时分开记录输入采样seed与解码seed，固定输入hash后才能比较纯解码策略。自回归后端额外保留原token、EOS、预算与解码停止原因，扩散/flow后端按其实际采样记录，不能强造token字段。默认保持各后端已验证生成规则。MeshAnything语法约束采样作为独立实验profile，必须经过同输入对照后才能推荐；不能直接删坏token/绕过停止继续拼面并宣称修复。增加token长度、量化档数或MC分辨率不作为通用质量优化手段。

**输出：** 原始 AI 网格、模型输入/输出来源链、实际面数、问题报告。候选即使质量不足也可单独查看，状态为“待修复/待复核”。

### 步骤 4：修复、朝向与贴合

先检查接缝、内部开口和逐组件法线证据，再做局部修复，最后受约束贴合参考高模。保留原 AI，不覆盖手工编辑结果。

复用现有算法时去掉固定输入路径、固定边界数量和按本岩壁假设的无条件翻面/补洞。未知开口提供标记与前后对比；不能把所有五边环都填掉。源模型边索引不能直接复制到拓扑不同的 AI 网格。

贴合限制位移、面旋转、新相交、轮廓变化与跨层对应；记录接受、拒绝和未处理区域。平均距离下降不能代替棱角、轮廓和烘焙正确性判断。

**输出：** 新修复/贴合版本、原始候选对照、几何与形状报告。未满足条件时停在可检查的候选，不自动进入“全部通过”。

### 步骤 5：连续 LOD

1.1.21传统LOD以保留百分比为主，明确LOD0或前一级基准，同时显示预计/实际三角面数及预算约束。50%逐级保留是可选起点，不是通用标准；屏幕大小和误差共同决定档位。100000/10000/3000/1000/300及AI候选1200/800/500/300均为旧案例预算，不作为通用默认。Nanite准备走独立源资产与Fallback配置，不强制此五档流程。

每一级从上一级实际结果生成，保存父级哈希和合并记录。保留外轮廓与主要结构约束，每级重检；质量约束无法满足预算时保留实际面数及原因，不偷偷放宽检查。

这是必须实现的连续减面步骤，不是可留到后续版本的可选增强。AI候选分支先获得可接受的修复/贴合基底；原高模保形分支从真实高模开始；两者都逐档减面，不得一次压到最低预算。公开档位之间保留有记录的中间步骤。高模兼作结构检查和烘焙来源，实际处理方式及输入始终明示。

画布切换 LOD 时切换具体模型和对应报告，不重复生成。结果总结标清各级面数，近景/远景适用性由实际场景和视觉复核决定。

**输出：** LOD 组与当前选中结果。后续 UV、Cage、烘焙绑定具体 LOD；不能把 LOD0 的通过状态继承给 LOD1。

### 步骤 6：UV 展开与打包

先检查选中低模是否已有可用 UV 与已验证的原贴图对应；不要无条件重新展开所有输入。UI 保持一个 UV 节点，在内部展示“复用原图集”或“新 UV＋材质对烘”及理由，未实现能力不显示为可用开关。

#### 6A. 原图集复用：可选、受验证能力

适用于拓扑不变的直接复用，或明确选择具备 UV/材质属性约束的传统简化算法。简化必须考虑 UV 接缝、材质边界、角点属性与纹理误差，不自动移动、旋转、缩放或重新打包原图集。对合并后角点插值和源表面对应做检测，贴图/材质引用可复用时才标“已验证复用”。

“复用原图集”不等于减面后逐顶点 UV 数组完全相同，更不保证每个表面点的颜色完全不变；三角形变化会改变插值。需要保留缝/边界时可能无法达到目标面数，应保留较高面数并报告原因。即使颜色贴图可复用，低模法线/切线变化也可能要求重烘 Normal。现有 TopoForge 传统实现尚未保留这些属性，不能直接启用此模式。

对 AI 新拓扑尝试投射源 UV 属于后续可评估方案：原 UV 接缝可能穿过新的三角形，简单最近点/逐顶点 UV 复制会跨岛插值；需要切分三角形、可靠的表面/图岛对应与独立检查，并可能改变面数。首版不依赖这种能力通过验收。用户锁定“必须复用原图集”而 AI 路线不支持时，说明冲突并保留源资产，不静默改用传统减面。

#### 6B. 新 UV＋材质对烘：拓扑变化后的默认路线（含AI低模及保形减面）

已有 UV/贴图的源高模保持原样。对选中的 AI/LOD 结果制作新的目标 UV；随后用低模 UV 定位低模表面、投射到高模、通过命中三角形的重心坐标取得源角点 UV，再读取对应材质和贴图，将颜色/属性写入目标图集。保留的是材质外观与来源，不是原 UV 布局。灰模输入仍可做几何烘焙，不能伪造源材质。

在选中的低模副本上制作。以 xatlas 做分岛/参数化/打包基础；结构切缝与人工约束需要适配和验证，不能声称默认自动分岛必然符合美术意图。可导入外部完成的 UV 或带明确元数据的切缝；GLB/OBJ 不保证保存 DCC 专属切缝标记，缺少时不能假称已保留。

xatlas 的接缝会分裂顶点，必须用 `xref` 保留源映射，并同步法线、材质与其他角点属性。Open3D UVAtlas 只作为对照候选，不为同一能力默认安装两套库。

常用选项：贴图尺寸、像素留白、规整偏好、保留手工缝。规整是偏好，不强迫所有岛变矩形；不固定 16 岛和 60% 覆盖。首版默认 2K，4K 在资源和检测能力支持时开放。

结构切缝默认优先考虑凹进去的缝隙、低可见区域和必要的结构边界，并保护用户锁定的切缝。必须依据统一朝向后的凹凸几何及结构分区评估，不能把所有大二面角都当成凹槽。UV岛尽量方正、方向规整、便于绘制；以低拉伸、合理纹素密度和无非法重叠为前提，不强拉矩形。展示3D切缝叠加、UV布局和棋盘格，使用户能核对凹槽切缝与岛形。仅调用xatlas默认展开不算完成结构UV要求；禁止以每三角面独立铺岛的调试布局冒充最终UV。

提供 UV 图和棋盘格，分别报告重叠、翻转、退化、非有限值、拉伸、纹素密度、有效覆盖、岛间及 tile 边缘留白。三角低模采用独立 UV profile，不套四边面比例门。现有 `uv_complete` 只代表局部流程状态，不能充当完整质量结论。

现有光栅检测上限 4096，超出时要显式不支持或另开发验证，不降采样后声称更高分辨率已通过。LOD 拓扑不同默认分别展开；共享图集和 UV 转移另行验证。

每档 LOD 的材质对烘默认从只读原高模/源贴图出发，避免从上一级已重采样贴图反复对烘而积累模糊。共享图集或复用上一档贴图只在明确支持并验证对应后启用。

**验收：** 几何表面、面关联和变换保持；允许有映射记录的 UV 接缝顶点分裂，不能以顶点数完全相同为标准；保存重开后 UV 一致；无检出非法重叠/翻转；留白按实际输出分辨率验证；拉伸和利用率真实报告。

### 步骤 7：烘焙准备与 Cage 检查

自动关联来源高模，用户可以检查但不能被代理替换。显式记录目标低模、UV 版本、源材质、法线/平滑设置、射线参数和 Cage。

输出前固定用于烘焙和导出的三角化/切线约定，防止导出后换三角线造成法线差异。Cage 必须与目标顶点/面对应一致，检查自交和朝向。Cage 无自交不代表射线一定命中正确源面。

先做低分辨率诊断：NORMAL + 独立命中检查，输出未命中掩码并定位低模面。EMIT 白图仅用于命中诊断，不当作 Base Color。诊断图有 TEST_ONLY 标记，不混入正式导出。

漏烘需要区分 Cage 范围、低模跨层、源缺面和法线问题；不能只增大射线距离直到画面有颜色。历史 12.1943% 漏烘案例是必须保留的负向回归。

**验收：** 每级单独记录分母、排除边缘、射线范围、漏烘位置及限制。是否命中与是否命中正确表面分开判断；缺证据不标合格。

### 步骤 8：正式烘焙与基础材质组装

诊断处理完成后才执行正式分辨率。按通道分阶段运行，结果原子提交；某通道失败不删除其他成功成果，也不把整组标成完整。

烘焙执行链为：低模 UV 光栅化 → 插值低模位置/角点法线 → Cage 射线 → 高模三角形及重心坐标 → 高模 UV/角点法线/材质采样 → 通道生成 → 扩边与接缝检测。命中位置不能直接充当纹理坐标；Open3D `primitive_uvs` 是重心坐标。使用 MikkTSpace 时保留角点切线和符号，烘焙与导出三角化必须一致。开放岩壁不能依赖要求闭合表面的 signed-distance 正负号决定朝向。

| 通道 | 来源与处理 | 必须说明 |
|---|---|---|
| Normal | 高模到低模的切线空间烘焙 | 切线、三角化、Y 方向和强度约定；不重复叠加已经包含的细节 |
| Base Color | 原高模可用颜色/材质的无光照转移 | 不把白色命中图当底色；原贴图有固定阴影时提示，自动去光照不纳入首版默认能力 |
| AO | 真实几何烘焙 | 标注距离/范围；不能由底色转灰度冒充 |
| Roughness | 原材质可解释属性转移 | 缺失时用户选择基础值并标“默认参数”，不声称真实恢复 |
| Metallic | 原材质属性；非金属可选明确常量 0 | 不用颜色亮暗推断金属度 |
| Height 等 | 非首版必需 | 没有真实输出则显示未生成，不用假图补齐 |

完整材质组最低定义：可用的 Base Color、Normal、Roughness、Metallic 配置，以及本流程要求的 AO；常量属性可用于基础材质，但必须显示来源，导出按目标要求保留常量或生成对应常量图。缺少源颜色/材质时用户可以选择中性基础材质完成可渲染组装，界面标“基础材质”，不能称已还原原材质。无依据自动生成新材质不在本版范围。

Base Color 按颜色空间处理；Normal、AO、Roughness、Metallic 按非颜色数据处理。源材质含程序节点、透明/透射或不支持 shader 时列出限制，不静默拍一张有光照截图替代属性。

**已有材质的对烘规则：** Base Color、Roughness、Metallic 及受支持的 Emissive 等按各自源 UV 集、纹理变换、采样器、通道打包和材质因子求值；不只复制文件或换 UV 标签。保留细节受源贴图清晰度、目标纹素密度和投射误差约束，不能承诺任意低模/低分辨率无损还原。首版明确支持的材质模型之外，提示先转换/烘成标准纹理，不暗中依赖 Blender。

源切线空间 Normal 不按 RGB 当颜色直接转贴：先在源三角形切线基下解码，结合源角点法线、镜像符号及必要坐标变换，得到源表面法线，再转换到目标低模切线空间。区分“仅高模几何细节”和“包含源法线贴图细节”两种来源，防止同一细节叠加两次。Bump/Displacement 或无法解释的源着色器明确标不支持，不能静默遗漏后声称完整恢复。

源 AO 作为已有材质数据可保留/转移并标明来源；新几何 AO 单独计算。产品必须明确选择使用哪一份或记录受控组合，不能无提示相乘造成重复变暗。验证目标材质时使用相同相机、统一光照和色彩管理，另外查看纯 Base Color；不能用不同灯光掩盖颜色漂移。

正式贴图做扩边与 mipmap 接缝检查，保留原始分通道文件。原则上 Base Color 不重复乘入已另存的 AO，避免目标引擎双重变暗。

### 步骤 9：完整材质结果与导出

结果节点默认显示完整材质渲染封面；双击可旋转观察并切换统一光照、线框、通道。显示当前 LOD、实际纹理分辨率、质量状态与通道来源。

生成材质总结板，重点检查裂缝/凹凸位置、接缝、明暗异常和轮廓。至少两种光照条件下检查，避免固定打光掩盖烘焙问题。用户可回到 UV/Cage 阶段重做受影响部分。

优先导出 GLB，以及含 OBJ/MTL/贴图/报告的受验证资产包；编辑历史保留在画布资产项目中，不承诺生成 `.blend`。FBX/UE 专用导出须单独验证后启用。源工具专属 shader 或格式不能表达的属性明确提示。LOD 首版可以分别导出并附清单，不假称引擎必然自动识别 LOD 层级。

导出内容只包含选中结果、其贴图与必要元数据；不包含隐藏高模、失败候选、Cage 和诊断图，除非用户明确选择研究工程导出。原高模仍留在本地项目。

记录单位、坐标轴、UV、法线约定和目标配置。glTF ORM 为 R=AO/G=Roughness/B=Metallic；其他目标按实际约定配置。法线绿色通道转换只在源/目标约定不同且已验证时执行。

**验收：** 导出重导入后面数/UV/材质关联一致，贴图不缺失，法线方向正确；代表性结果在目标查看器或引擎内确认。单纯浏览器预览成功不是引擎验收完成。

## 6. 高模显示与内存优化规划

### 6.1 基本策略

**画布只读元数据和封面；用户打开 3D 面板时才加载受限代理；真正高模由后台按阶段使用。**

不得把高模数组、贴图 base64 或大块 JSON 存进 React 状态、localStorage、画布保存文档或 Agent 上下文。前端只持资产 ID、版本与受控 URL。项目打开不遍历下载所有模型原件。

磁盘文件小不代表内存小：索引、顶点分裂、法线、UV、BVH、三角化、解压纹理、GPU 上传和临时副本都要计入。预检只给估算并说明误差，通过实测形成后端/格式对应的峰值倍率，不用文件大小直接承诺能处理。

### 6.2 初始预算（规划值，不是已实测支持规格）

以下作为实现起点，可由性能回归调整；提高预算必须有实测，降低预算只影响预览时不得改制作原件。

| 资源 | 初始策略 | 达到上限时 |
|---|---|---|
| 可见节点封面 | 长边 640px，最多 2 个请求并发 | 排队/延迟，离屏取消未完成读取 |
| 活跃 3D 面板 | 同一画布 1 个 WebGL context | 在同一面板切换，关闭时释放资源 |
| 默认高模显示代理 | 目标 ≤100,000 三角面，低配档 ≤50,000 | 进一步简化显示代理或只显示封面 |
| 对比查看几何 | 默认合计 ≤200,000 三角面 | 顺序切换，不同时加载两个超预算模型 |
| 查看器纹理 | 默认每通道 ≤2K，4K 明确升级且按预算加载 | 降预览分辨率，正式烘焙原图保持 |
| GPU 预览预算 | 应用侧估算上限初始 256 MiB，含几何/纹理/mipmap/渲染目标 | 先减纹理与对比负载；不能准确测实际 VRAM时标估算 |
| 重任务并发 | 默认 1 个 AI/几何/烘焙重任务；已有 ComfyUI GPU 工作时等待或按明确资源策略调度 | 排队，不抢占或卸载他人模型 |
| 后台 RAM | 总上限初始不超过 min(物理 RAM 的 40%, 24 GiB)；启动预算还受当前可用 RAM 约束，保留至少 max(8 GiB, 物理 RAM 的 25%) | 拒绝启动/降低可降级任务负载；监测超预算时安全取消，不自动换低精度源 |
| 可重建 3D 代理缓存 | 初始目标 2 GiB，与现有图片缓存独立统计；任务临时区另计 | 仅淘汰未使用代理，不清理原件/正式结果 |
| 单文件导入 | 初版沿用现有 2 GiB 资产上限，同时受解码/面数/内存门限制 | 明确拒绝或要求外部拆分；超大外部资产引用留后续设计 |

单个 4K RGBA8 纹理未压缩约 64 MiB，完整 mip 链约 85 MiB；四张就约 341 MiB，双材质对比可翻倍，尚未计几何和渲染目标。因此不能按 PNG/JPEG 文件大小估算显存。纹理压缩只有目标浏览器/格式实际验证后才计入收益。

RAM 上限是受管理任务及其子进程的合计工作预算，不是给每个子进程各分一份。启动时按 available memory 计算，运行时监测进程树 RSS；允许给当前任务结束保存日志的短暂余量，但半成品不得成为有效模型。对不能分块的第三方解析器承认限制，不能以“流式上传”冒充“流式解析”。

### 6.3 导入与后台处理优化

- 文件上传/复制和哈希使用分块流，避免浏览器和后端同时持有整个文件；本机大文件后续可通过受控选择器优化搬运，但不得接受任意路径字符串直接读盘。
- 大模型解析、三角化、结构检查、代理生成和封面渲染都在受管理子进程完成，不在 HTTP 请求线程同步等待。
- 先低成本元数据检查，再决定是否允许全量解析。格式没有可靠轻量面数信息时，在受限进程探测；超限明确停止，不无限尝试。
- 支持磁盘中间产物和阶段边界释放内存；只在算法支持时分块，不能假称所有 BVH/模型推理都可流式。
- MC/SDF 等体素处理按实际边长的立方估算内存；提高 MC 分辨率不是线性成本。高模输入采样和空间索引单独计峰值，8192 点模型输入不代表上游只占8192点内存。
- 同一阶段避免重复复制数组和重复构建空间索引；复用条件包含模型与参数哈希，缓存失效明确。
- 原件封面渲染同样受预算约束；无法安全加载时显示代理封面及说明，不为了“出封面”导致服务崩溃。

### 6.4 3D 查看器优化

- 按需加载查看器代码、模型和纹理；模型代理从后端读取，浏览器不先加载高模再自行减面。
- 若需前端解码/转换，放 Web Worker 并使用可转移缓冲；GPU 资源创建仍受预算约束。
- 默认按需渲染：相机/模型/灯光变化才更新，页面隐藏或查看器关闭停止渲染循环；缩小屏幕像素比和阴影配置作为预览降级策略。
- LOD 切换先释放或有限保留旧档，不把所有 LOD 和所有原始贴图同时解码。关闭时 dispose geometry/material/texture，释放对象 URL、事件和 worker。
- 能力检测必须覆盖 WebGL 不可用、context lost 和软件渲染。失败时退回静态封面及下载，不影响项目编辑。
- 高模细节可请求后台局部/高质量静态渲染；这不是浏览器完整高模实时预览，需分别标注。

### 6.5 原生 3D 引擎与其他 GPU 工作的资源协调

几何CPU阶段、所选AI执行器GPU阶段和独立CPU/DX11烘焙候选分别申报资源。首版先验证CPU基线；Open3D/Embree的GPU能力不等同NVIDIA CUDA烘焙。前台任务栏可以统一，但不同执行器状态不能假装是ComfyUI prompt。

资源协调不构成后端依赖。没有 ComfyUI 时直接按实际 GPU 可用资源调度；它存在且正在运行时，才将其作为另一资源使用者处理。3D 与图像/视频任务的状态与故障隔离，不能用一方离线推导另一方不可用。

计算显存与浏览器 256 MiB 预览预算分开管理。为每个后端/版本/精度/输入规模/贴图分辨率建立实测资源档案，启动前用预测峰值与当前可用 VRAM 比较；初始安全余量取 `max(1 GiB, 总 VRAM 的 15%)`，只有“本阶段预测峰值 + 安全余量 ≤ 当前可用 VRAM”时才准入。模型加载、预处理、推理、烘焙场景/BVH 与渲染目标的峰值均需覆盖，不能只计算权重大小。

峰值未知时标记“资源尚未验证”，先用小规模输入做受控试运行建立档案，不因 GPU 空闲就自动提交全量高模。运行时监测实际显存和进程状态，超预算走可控失败；不同输入的峰值预测有误差，不承诺准入后绝不 OOM。上述余量也是待性能实测调整的初始策略，不是硬件最低规格声明。

默认先完成或等待现有 GPU 工作，再运行下一重任务。重启画布不能自动停止独立 ComfyUI 或用户 Blender。取消只终止当前任务拥有、PID 与创建时间匹配的进程树。

烘焙先低分辨率诊断，再正式通道；CPU/GPU 渲染器切换必须记录并验证差异。OOM 后保留阶段成果，用户可选降低烘焙分辨率、改 CPU 或分批；不能自动减掉原高模细节却继续报告同质量成功。

## 7. 数据协议、保存与失效规则

### 7.1 最小数据结构

每个资产/任务至少记录：`assetId/jobId`、内容哈希、资产角色、格式、尺寸/面数、单位/变换、直接父级版本、引擎/模型版本、参数指纹、阶段状态、质量分项、输出清单、资源测量、耗时和错误摘要。

通用AI运行额外绑定 `adapterId/adapterVersion/modelId/weightsHash/parameterSchemaVersion/resolvedParameters` 及能力快照。本机路径与运行环境绑定独立于可移植节点配置；缺适配器时历史结果可查看，新计算显示缺项。节点配置草稿与已完成结果配方分别记录，旧任务晚完成不覆盖新配置选择，模型切换不触发自动昂贵重跑。

导入快照必须保留角点法线/切线及 handedness、镜像变换、平滑/硬边、三角化对应、UV 集及材质选用索引、面材质 ID、顶点色、PBR 参数、纹理色彩空间/采样器/UV 变换。不能只存 vertices/faces 后再期待恢复材质。首版不支持的多材质输入可明确拒绝后续处理，但原件与识别信息不能丢失。

模型结果引用 `sourceModel`、`geometryVersion`、`uvVersion`；烘焙额外引用 `cageVersion`、源法线/材质、shader/纹理依赖和目标导出配置。属性来源区分 `baked`、`transferred`、`user_constant`、`missing`，不可笼统都标“AI生成”。

新增 UV/材质对应记录：`uvPolicy`（复用图集/新图集对烘）、`sourceUvVersion`、`targetUvVersion`、源/目标 UV 集及每通道材质绑定、源/目标切线约定、原贴图哈希、重投射参数和验证状态。源 UV 改变使相应对烘结果失效；目标 UV 改变使目标贴图失效，不触发覆盖或重新展开源 UV。缓存不得仅以几何哈希判断可复用。

画布数据只存这些引用；大模型、贴图、日志与报告文件存磁盘。模型/贴图按白名单、容量、路径和哈希验证，数组加载关闭 pickle，不允许节点包执行任意 Python/shell。

### 7.2 任务与质量状态分离

任务：`queued → preparing → running(stage) → validating → ready_for_review / completed / completed_with_issues / failed / cancelled`。

质量：几何、轮廓/贴合、UV、Cage、烘焙、材质、导出分别为 `not_tested / pass / needs_review / fail / stale`。completed 只代表任务完成，不能推导“生产合格”。

当前页面作为项目单写入口：后台产出文件与回执，页面接收真实素材、结果节点和来源连线，并完成 revision 保存。关闭页面后任务可以结束，重连时幂等领取；无法写入时显示“待接收”，不能直接覆盖 `project.json`。

### 7.3 修改后从哪里重做

| 改动 | 保留 | 失效或重做 |
|---|---|---|
| 原高模几何/变换/朝向 | 历史结果 | 当前 AI/贴合及相关下游 |
| AI 参数/模型 | 原件、已有候选 | 新候选与其后续链 |
| 低模拓扑或某级 LOD | 上游结果 | 该级及下游 UV/Cage/烘焙 |
| 低模位置或用于投射的法线 | 可保留 UV，但需检查失真 | Cage、命中/对应缓存、所有依赖该投射的颜色/属性/Normal/AO通道及相关报告 |
| 仅着色法线/切线/平滑，未改变投射 | 几何、UV、已验证未受影响的对应 | Normal及材质显示/导出报告；若影响实际射线则按上一行使全部投射通道失效 |
| UV/切缝/图集布局 | 几何 | 对应贴图与烘焙报告 |
| 源 UV/材质 UV 绑定/纹理变换 | 几何、可独立保留的目标 UV | 源采样对应、相关材质对烘；依赖源图集的复用/转移报告 |
| 源材质或源贴图 | 几何/UV | 相关材质通道，不无故重新 AI 推理 |
| Cage/射线参数 | 几何/UV | 相应烘焙结果 |
| 仅显示代理/灯光 | 制作资产与报告 | 对应封面/展示缓存 |

断线恢复不自动重复推理；已完成阶段通过哈希复用。运行中上游被修改，旧任务可作为历史输出保存，但不能自动激活到新版本流程。

持久化顺序固定为：任务私有临时产物 → 校验/哈希 → 同盘原子提交资产及完成清单 → 后台可领取回执 → 当前页幂等接收 → 保存revision确认。资产完成与页面领取是不同事务；页面关闭时保留待领取。崩溃发生在回执前时可从有效完成清单恢复，禁止仅凭文件存在判成功。未完成阶段没有受支持检查点时只能重跑该阶段，不承诺任意进度续算。取消与成功用持久化状态转换裁决，取消不能把半文件转成成功；已完整提交的资产按终态保留且不重复生成。引擎版本变化不默认兼容旧检查点。

## 9. 性能与故障验收计划

### 9.1 输入矩阵

- 几何规模：约 10 万、100 万、500 万、1000 万三角面的代表模型；高档用于探测极限，并非全部必须支持。超预算应可解释地拒绝，不能导致画布或系统失去响应。
- 来源：扫描高模、人工高模、AI 高模；带纹理/无纹理、开放岩壁、多个组件、退化/重复/错误法线、中文路径、缺失外链图片。
- 纹理：1K/2K/4K，单套及多套材质检测。超出首版支持的材质/UDIM 仅做明确拒绝与保留原件的验收。
- UV/对烘：有源 UV 和贴图的高模、新拓扑 AI 低模、无源材质、故意错源 UV 集、源镜像/平铺、目标冲突重叠、源法线细节、纹理因子与通道打包、低纹素密度。源图案用棋盘、文字/编号和跨接缝色块检查方向、错岛、拉伸与丢细节；多视角检查目标材质和纯颜色图。用户锁定图集但执行器不支持时必须停在可解释状态，不假称已保留。
- 参考硬件：现有 RTX 3090 Ti 24GB、64GB RAM 机器。8GB和12GB分别建立真实硬件验证档，记录型号/架构、驱动、RAM、后端、精度、冷/热启动、最长受支持输出及全阶段峰值；仅受控预算夹具只能验证拒绝/恢复，不能授予实际硬件支持状态。未取得对应硬件证据时明确写“待验证”，不以24GB卡限额冒充8GB/12GB验收。
- 低显存链采用单个AI任务、模型阶段退出后释放显存、CPU几何/UV/烘焙和受限单查看器。CPU路线仍有RAM/耗时/解析峰值门；原高模不降格为代理。分别测试AI几何、2K完整材质链和4K可选输出，不能以单步成功宣称整链支持。

### 9.2 初始性能目标

以下为验收目标，尚未测得；正式发布报告必须写实测设备、样本和冷/热条件。

| 场景 | 目标与测法 |
|---|---|
| 100 个模型节点项目，已有封面缓存 | 开项目不读取任何源高模或完整模型网格；参考机 1920×1080，重复10次测可交互时间 P95，目标 ≤3秒 |
| 单个 ≤10万面代理、2K 预览贴图 | 参考机旋转稳定目标 ≥30 FPS；记录帧时间，不用静态截图替代 |
| 高模导入/推理/烘焙期间 | 画布仍可平移、编辑备注、保存；重计算不在前端主线程；记录长任务及响应延迟 |
| 连续打开/关闭查看器20次 | 关闭后受管理的 WebGL 资源计数归零；等待GC后的内存趋势无持续阶梯增长，记录可测数据与局限 |
| 缓存与项目重开 | 命中代理/封面缓存，变更源哈希后失效；旧报告不误复用 |
| 超 RAM/VRAM 或 WebGL 不可用 | 可控失败/静态预览，原件与已完成成果保留，服务仍可响应 |

导入、预处理、推理、修复、UV 和烘焙分别记录时间、进程树 RAM 峰值、GPU 峰值或采样估算、读写量及磁盘缓存命中。不能用单次 146 秒 AI 案例预测任意高模总耗时。

### 9.3 故障与恢复

覆盖上传取消、磁盘不足、解析崩溃、模型缺失、DLL 不匹配、推理 OOM、烘焙失败、手工修改父级、进程被关闭、后端重启、浏览器关闭、重复回执、项目只读/保存冲突、外部贴图缺失和坏文件。

所有失败验证原件哈希不变；半成品不变成功；取消只影响本任务；恢复不会重复昂贵推理；结果只能由当前画布保存。现有图像/视频生成、模型列表、节点库、缩略图和项目更新流程保持回归通过。

### 9.4 独立于 ComfyUI 和 Blender 的专项验收

- 在未安装 ComfyUI、没有其目录和环境变量、没有 H3 模型包、8188 不可访问的隔离环境中，配置 3D 自身依赖，完成画布启动、模型导入、代理预览、AI 候选、几何/UV/烘焙和导出。分阶段测试可以用夹具，最终端到端需要真实 3D 引擎证据，不能只用 mock 证明全流程可用。
- 在配置中仅启用 3D，验证启动器和 Agent 不自动拉起 ComfyUI、不下载图像/视频模型、不因 ComfyUI 离线而禁用 3D 按钮。
- 3D 与 ComfyUI 同时启用时，一方启动失败/断线不影响另一方任务及项目保存；共享 GPU 的等待提示说明真实原因。
- 重启、取消和结果恢复仅操作对应 3D job 与其拥有的进程，不调用 ComfyUI 全局 interrupt 来取消原生几何、烘焙或 AI 任务。
- 在未安装 Blender、无其可执行文件、无 `bpy`/`mathutils` 包、无 Blender Python 的干净环境完成真实端到端流程；禁用网络验证已配置环境不临时下载 Blender。检查依赖清单与进程树，不能隐藏启动 Blender 或偷偷借用另一个环境。
- 无 Blender 时导入 `.blend` 应给明确的格式转换说明；不得把“不支持原生工程文件”误报成整个 3D 引擎故障。可选外部 DCC 精修不计入普通样本全流程依赖。

## 本轮 UV 试验协议（1.1.10）

- 输入语义：约 1,998,143 三角面的输入是已制作高模，不称扫描原始模型；原始资产永久保留。本例没有可继承的源 UV/贴图。其他已带 UV/材质模型必须走保留或对烘分支，不能按本例假设。
- 已通过本例几何复核的修复、定向、贴合结果 1772 面作为本轮测试 LOD0，依次为 1200/800/500/300 面。此编号不表示生产项目的最高档预算只能是 1772 面。需要更高最高档时另定目标，不用逆细分冒充源细节。
- 当前页显示五级实际 GLB，各自计数与原高模来源，提供下载。不得五个节点都引用同一低模/缩略图。保留已接受减面链；清除旧失败测试节点仅影响节点，保留素材与诊断记录。
- 同一 LOD0、固定面顺序进行结构分缝基线、CPU AO+大块面+凹角分缝，以及 PartField/SAMesh 的真实神经分区对照。AI 只建议分区，UV 展开仍由几何算法完成；不得以几何启发式结果冒充 AI 推理。
- AO 在原高模场景发射确定性半球射线，记录低高表面接近度/朝向支持覆盖率；不把暗面本身当作必须切开的条件。使用凹角、大块面边界和 AO 共同决定候选缝。凸面/暗面误切、碎岛、不可见缝需视觉复核。
- 外部 AI 标签必须绑定源文件 SHA256、原面计数、已核对的逐面双射顺序；归一化需记录可逆变换。不能重网格后无映射地直接赋予标签。仅本地研究，不随开源包分发许可未明确的代码或非商业权重。
- 对照固定分辨率 1024、间距 8px，明确记录各路参数、耗时、岛数、伸展、纹素密度差、像素重叠和间距。零像素碰撞不等于穷尽亚像素证明；方正是受形状/失真约束的优化目标，不强制每岛拉成矩形。
- CPU 基线与 AO 独立于 Blender/ComfyUI；AI 环境、权重、缓存放 D 盘隔离，串行 GPU 试验，记录实测峰值。24GB 本机成功不推定 8/12GB 成功。
- 先选定可接受的 LOD0 UV，再沿减面谱系转移共享 atlas 到 LOD1–4，验缝/拉伸/叠岛，必要时同 atlas 局部修复。当前展示全部 LOD 并不代表已完成跨 LOD UV 共享。高模通常作为烘焙来源，不为对烘强求高低同拓扑/同UV。
- 本轮不烘焙，不把纯棋盘图称为表面失真检查；材质/法线/AO完整贴图及共享 atlas 均分别验收。
